## What worked

1. **"Substrate-depth interpretation" was the right call.**
   The 17th mandate re-issued V80's wording verbatim. Reading it literally would have meant constructing a V5 blueprint less than 24 hours after V4 landed — that's blueprint-thinness, not depth. V80 close DEC §8 explicitly said V81+ continues against V4. V81 honored both the spirit of the mandate (iterate against the blueprint) and the discipline of V80 close (don't ship V5 prematurely). **Lesson**: when a strategic-pivot blueprint just landed, the next arc's job is to PROVE the blueprint, not REPLACE it. Successive blueprints without depth between them is substrate inflation.

2. **30-LOC arg-parsing block closed a 2-arc retro debt.**
   V79 retro flagged `V78_iter_*.md` overwrite. V80 retro repeated the flag with no action. V81.4 took the implementation: read positional iter argument, then drain remaining args looking for `--arc-label` (long-form + `=value` form), default to `V78` for backward compat. Smoke-tested via 4 invocations covering all paths. Backward-compat is preserved exactly: `score_all.sh 0` still writes to `V78_iter_0.md`. **Lesson**: retro-flagged technical debts that aren't urgent compound across arcs; a 30-LOC fix in a slow arc is worth more than the same fix postponed to a "real" infrastructure arc that never comes.

3. **Curated commentary for canonical cases reuses CFD knowledge directly.**
   NACA 0012 commentary cites AGARD AR-138 + NASA TM-4741 + Menter 1994 k-ω SST. Backward-facing step cites Driver-Seegmiller 1985 + Versteeg & Malalasekera + OpenFOAM pitzDaily tutorial. These citations would have failed Codex review if hallucinated; they're known canonical references in any CFD engineer's mental library. **Lesson**: the "human-curated" constraint of V80 reverse-stop #7 isn't a chore — it's the ONLY way to get citation-grounded text. LLM-generated CFD commentary at runtime would routinely cite fictional papers; static curation lets the engineer-author guarantee provenance.

4. **V4.A/V4.D e2e proof tests landed cleanly after one fix.**
   8 specs · 7 passed on first run · 1 needed a Playwright-specific fix (beforeEach `addInitScript` was firing on `page.reload()` and wiping the localStorage flag the test had just set). Fix was 1 paragraph of removal + a comment explaining why we can't pre-clear via init script for a reload-survival test. **Lesson**: Playwright's `addInitScript` fires on EVERY navigation, including reloads. Don't use it as a "once at test start" mechanism — it isn't.

## What surprised us

1. **Baseline 77 had inter-test state contamination.**
   Test 76 ends at step=4&view=residuals (SolverInflightTicker active SSE EventSource); test 77 navigates to step=5&view=report. The Playwright page object survives, but the EventSource from test 76 doesn't clean up before test 77's React tree renders the comparator. This caused a sub-pixel rendering difference that the isolated-run capture didn't see (because in isolation there is no prior SSE state). Re-capturing baseline 77 under full-suite state fixed it. **Lesson**: visual baselines that come after SSE-mounting tests need to be captured under full-suite state, not in isolation. Add this to V82 charter as a hygiene rule, similar to V79's "sibling controls change → re-snap" rule.

2. **Intermittent vitest flake at ~33% appeared during stability scoring.**
   Iter-2 first attempt: stability=70 due to 1-of-3 vitest run failure. 3 subsequent manual runs all pass. Iter-2 retry + iter-3 both pass cleanly. The flake didn't survive investigation. This is exactly the test infrastructure noise V79 retro warned about; not a substrate regression but a real stability scorer artifact. **Lesson**: the V78 stability scorer correctly flagged the noise; the response was honest re-run + disclosure, not silent retry. The retro queue grows by one item (vitest parallel worker race).

3. **4-arc no-scoring-change streak feels routine now.**
   V78 was "harder work, same score" (threshold tightening). V79 was "more work, same score" (zero scoring changes). V80 was "strategic pivot, same score" (new blueprint, zero scoring changes). V81 is "substrate depth on existing blueprint, same score". Each arc made the constraint feel more natural, not less restrictive. **Lesson**: the scoring framework was right-sized at V77 close; subsequent arcs don't need to grow it. The pillar at 100 measures different substrate now than it did at V77; that IS progress.

4. **Score aggregator filename hygiene unblocked a small future quality-of-life win** that compounds over arcs. V82+ now invokes `score_all.sh N --arc-label V82` and gets per-arc score reports without manual copy. Estimated saved labor: ~2 minutes per close gate × 5 arcs/year = 10 min/year — small but free.

## What I'd do differently

- **Investigate the vitest flake at iter-2 rather than just retrying.** V81 chose honest disclosure + retry because the substrate was orthogonal to the flake. But the flake will recur in V82+; V82 retro will likely log it again. Worth a focused 30-minute investigation before V82 close.
- **Capture baseline 77 from full-suite from the start.** The isolated capture wasted ~6 minutes when the full-suite re-snap caught the difference. Add to V82 hygiene rule: new baselines that follow SSE-active tests MUST be captured under full-suite state.
