## What worked

1. **The V4 blueprint document was the load-bearing artifact, not the code.**
   The user mandate said "construct the next-stage blueprint". V80.1 landed a 4-contract blueprint document at `.planning/blueprints/v4/INDEX.md`. The subsequent V80.2/V80.3/V80.4 sub-DECs each map to a single V4 contract (V4.A→V80.2 · V4.B→V80.3 · V4.C→V80.4 · V4.D→V80.2). Having the blueprint FIRST made the sub-DECs trivially scope-bounded: build the component the blueprint specifies, no more no less.

2. **"Human-curated text in a static module" is the right answer to V130 + offline-LLM.**
   V80.3's `src/data/advisor_commentary.ts` is 120-ish lines of CFD expert commentary keyed by (case_id, step). It's reviewable in git. It carries citations (Ghia 1982 / Versteeg & Malalasekera / Ferziger & Perić / OpenFOAM User Guide). It can NEVER violate V130 (no runtime LLM call) because the values are baked into the bundle at compile time. **Lesson**: when the V130 invariant says "no runtime LLM", the answer isn't "stub the LLM call with empty strings" — the answer is "land a curated corpus and pretend the LLM was never going to do this well anyway".

3. **Same-data, two-visualization rule held cleanly for V80.4.**
   ReportComparisonV3 (V71 era) and ComparatorV4 (V80.4) both consume the same 17 Ghia 1982 reference points and the same `computeLidCavityComputed()` perturbation function. They render DIFFERENT visuals (overlay vs. side-by-side with worst-point highlight) but agree on the underlying data. The "max error 0.78%" claim in the existing TrustGate verdict and the new ComparatorV4 max-delta annotation come from the same compute path. No risk of "0.78% here · 1.2% there" inconsistency.

4. **Demo mode opt-in with `?demo=1` was a 1-component substrate.**
   V80.2's DemoBannerV4 is 170-ish lines. It reads `?demo=1` from useSearchParams, gates first-time hint chip vs full banner on that + localStorage, advances the tour via `setSearchParams`. No new routes. No new state container. localStorage key + URL query state is all it needs. **Lesson**: opt-in demo modes don't justify a separate app or route hierarchy; URL query + localStorage scales to 6-step tours fine.

Honest scope: V80.3 PROVES the contract works for one case; V81+ scales.

## What surprised us

1. **The V4 blueprint felt risky in advance, trivial in retrospect.**
   The 16th mandate's "construct the next-stage blueprint" felt like a "should I really add this layer" decision. In practice, the blueprint document was 320 lines of contracts (each ~50 lines). The code implementing each contract was ~100-200 lines. The blueprint did NOT need to be a multi-day artifact; it took the same shape as V3's Image-1..Image-8 structure (visual contracts with don't-drift-on bullets). **Lesson**: blueprint arcs aren't categorically larger than feature arcs. A blueprint is just feature scope organized one layer of abstraction up.

2. **Baselines 54 + 59 drift was exactly the V79 pattern repeating.**
   V79 baseline 63 drifted from a 4-button camera cluster vs single button. V80 baselines 54 + 59 drifted from V80.3 commentary cards added into the right panel + V80.4 comparator added into the report viewport. Same root cause: new content rendering into a previously-baselined panel. Same resolution: re-snap, document, move on. **Lesson**: every arc that adds visible substrate into Step-5 report or right-panel Advisor will drift baselines 54 + 59. This is now a **predictable** cost, not a surprise.

3. **V78 scorers absorbed V80 substrate with zero friction.**
   No scorer tweaks needed. The 8 commentary + 8 comparator contract tests ran through vitest (the underlying quality / functional pillars don't care about test count). The new SVG content rendered in baselines 54 + 59 was caught by visual-baseline.spec.ts (UX pillar's 100%-pass threshold), and the canonical re-snap path resolved both. **Lesson**: the V78 scoring framework is robust enough that a strategic pivot adding 1 blueprint + 3 components + 1 data module + 16 contract tests requires ZERO scorer adjustments. This is the load-bearing proof that "construct a new blueprint" doesn't have to mean "build a new measurement framework".

4. **The `V78_iter_N.md` overwrite trap struck again.**
   Same issue V79 retro flagged. Solved by copying outputs to `V80_iter_N.md` after each run. V79's retro suggested renaming the aggregator to `vN_fleet/score_all.sh <arc_label> <iter>` — V80 didn't make the change because it was orthogonal to V80's strategic-pivot goals. Carrying forward to V81+ retro queue.

## What I'd do differently

- **Land the curated commentary corpus for the full Gold-Standard 10 cases BEFORE the comparator** — would have made V80.4's "side-by-side complement to GoldDeltaPanel" claim land with stronger substrate. V80 went depth-first on one case (lid_driven_cavity) instead of breadth.
- **Add a `V80_iter_*.md` separation upstream** — `v78_fleet/score_all.sh` should accept an arc-label argument and write `V{arc}_iter_{N}.md`. Trivial change; the manual copy step is wasted effort. Add to V81 charter §X.
