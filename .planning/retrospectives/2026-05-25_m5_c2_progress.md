**Bug #2 — frontend hardcodes `?patch=engine`** (won't match generic cases):
- `ModeRendererPost.tsx:582` builds `surfaceVtpUrl = .../post/surface.vtp?patch=engine`.
  `engine` is an APU-bay patch; LDC has `fixedWalls`/`lid`, backward_step has its
  own. So surface overlay 404s on every non-APU case.
- Fix approach: derive the patch from the case's real boundary patches. Options:
  (a) a small `/post/patches` endpoint listing boundary patch names (the backend
  already knows them — `VTK/case_<idx>/boundary/*.vtp`), frontend picks the
  largest/first non-empty; (b) default to the internal volume surface instead of
  a named boundary patch. (a) is cleaner + reusable.

**Bug #3 — no GLB ⇒ viewport never mounts ⇒ overlays never render**:
- imported cases have STL but no GLB (`geometry/glb` 404, `geometry/stl` 200).
- `ModeRendererPost` gates `<ViewportV4 glbUrl=…>` on `hasGeom` (GLB present via
  `useGlbAvailability`); no GLB → `PostEmptyViewport`, so the VTP overlays (which
  attach onto the ViewportV4 kernel) never mount.
- Fix approach: mount ViewportV4 when EITHER glb OR a post VTP is available (the
  surface VTP can be the base actor), OR generate/serve a GLB for imported cases,
  OR relax the gate to mount an empty kernel that the VTP overlay populates.
  Cleanest: let the VTP surface be a first-class base actor when no GLB.
