## What worked

1. **Bookmark age forced honest disclosure**.
   V71.L → V72 → V73 → V74 → V75 each rolled "vtk.js carry" forward; V75 retro called it "time-bombed". V76 charter committed to closing it in §1, and the close DEC §5 honestly disclosed the discovery: most of the work was wiring, not greenfield. **Six-arc bookmarks should trigger a "what's already done?" audit before assuming the work is huge** — would have closed in V72 if we'd looked at viewport_kernel.ts then.

2. **Bundled substrate drop pattern carried over from V75.1**.
   All 5 Pillar-15 testids must coexist in the same DOM tree (otherwise mount_count=0 / camera=0 etc. partials happen). Authoring V76.1-V76.5 as one VtkCanvasV3 component in one commit > 5 separate sub-DECs each adding one testid. Sub-DEC numbering preserved for ledger continuity, but the actual code drop is atomic.

3. **Scorer iter-1 caught the literal-testid trap WHILE FIXING IT**.
   V76 charter §6 promised a scorer regex upgrade to accept template expressions. Iter-1 scored mount_count=1 — the regex correctly matched a doc comment containing the literal string, NOT the actual JSX which used `data-testid={mountTestId}`. **The fix was a one-line refactor** to two literal branches: `mode === "geometry" ? <div data-testid="vtk-canvas-mounted-geometry">` vs `<div data-testid="vtk-canvas-mounted-mesh">`. Iter-2 → 100. Without the upgraded regex, this would have been the 5th arc bitten.

4. **vtest mock pattern for vtk.js is reusable**.
   `vi.mock("@/visualization/viewport_kernel", () => ({ createKernel: vi.fn(...) }))` plus `HTMLCanvasElement.prototype.getContext = vi.fn(() => null)` for WebGL fallback path. Test ran in 919ms vs minutes for playwright. V77 should generalize this into a `tests/setup/vtkMock.ts` if more vtk-mounting components land.

## What was tightened in scope (vs the charter draft)

- **Real STL load** is unverified for placeholder cases — V76.2 charter said "Real STL/GLB load for current case mesh". In practice, `/api/cases/lid_driven_cavity/geometry/stl` returns 404 for non-imported cases. The component handles this via the `asset-missing` state (canvas mounts, shows "no rendered asset" hint, testid still present). V76 scoring doesn't depend on the URL returning 200, only on the testid presence. **Honest scope: V76 mounts the canvas; V77 should decide which cases have backend STL.**
- **Playwright e2e on baselines 61-68 deferred** — test definitions land; snapshot generation requires a running dev server + backend, which a session-level autonomous run can't validate without significant infra. V76 close DEC §5 discloses this honestly.
- **Camera presets** (front / top / iso) deferred to V77 — V76 only landed `Reset camera`. Industrial parity would add 3 more buttons; charter scope-creep prevented this.

## What surprised us

1. **viewport_kernel.ts was 90% of the work · already done in M-VIZ**.
   `attachStl`, `attachGltf`, `resetCamera`, `setPickHandler`, `dispose`, coplanar siblings — all built and tested in V61 era for the M-PANELS face-naming feature. V72-V75 inherited that infrastructure but never wired it into MainCanvasV3 because the placeholders "looked fine" and there was no scoring pressure. **Lesson: bookmarks rot in proportion to how invisible the unwired-but-built-infrastructure is.**

2. **WebGL fallback test was 1 line**.
   `HTMLCanvasElement.prototype.getContext = vi.fn(() => null)` in `beforeEach` made the WebGL detection return false, which routes to the fallback branch. The whole fallback testid + non-mount assertion runs in 2ms. Fragile-looking surfaces are often simple to test if you have the right hook.

3. **`react/jsx-runtime` exhaustive-deps lint did NOT complain** about omitting `loadStlFromUrl` from the deps array.
   The function is module-level constant; eslint treats it as stable. Earlier arcs (V73-V75) had spurious deps warnings on similar patterns and we added eslint-disable comments. V76 didn't need any — the existing convention works.

## What I'd do differently

- **Audit "carry" bookmarks every 3 arcs** — V71.L created the vtk.js carry. By V74 it was 3 arcs old; V75 retro called it "time-bombed". An audit at V74 close would have surfaced that `viewport_kernel.ts` already existed and the wiring was ≤200 LOC. Carry to V77 charter: process rule for any bookmark ≥3 arcs old = "spend 30 min looking before scoping".
- **Stop using doc comments that include literal testids** — V76 iter-1 mount_count=1 came from grep matching a comment block, not the JSX. Subtle but real noise in scorer signals. Convention going forward: use `data-testid prefix vtk-canvas-mounted` in prose, not the literal string.
- **Bundle close+retro into the close DEC body** — V73 / V74 / V75 / V76 all had separate retro files. The retro insights belong inside the close DEC's §5 / §8 sections. The separate retro file pattern is a v6.1 convention worth re-examining: 100% of useful insights end up duplicated in the close DEC anyway.
