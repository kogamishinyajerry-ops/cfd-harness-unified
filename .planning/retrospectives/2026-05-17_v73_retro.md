## What worked

1. **Anti-fraud threshold tightening** (B183 → B184).
   - Initial Pillar 12 thresholds (useQuery ≥8, endpoints ≥4, offline ≥8, tests ≥4) auto-passed at 100 because V72 substrate already met them. Recognized the fraud signal immediately, tightened to 12/5/18/8 so V73 work was required to clear. Result: substrate score dropped to 96, V73.5 lifted it back to 100 by actually wiring a 5th endpoint.

2. **axe-core surfaces real WCAG blockers**.
   - V72's wcag_baseline counted ARIA grep matches at source-time → 100/100. V73's wcag_runtime ran the audit against actual rendered pages → found 4 distinct violation classes (contrast / role / tablist / aria-controls). Every one was a real WCAG 2.1 AA blocker. Source-time grep was missing them entirely.

3. **UI pre-flight chosen over backend widening for V73.1**.
   - The honest root cause was an architectural mismatch (`/ai-review` uses `IMPORTED_DIR`, `/api/cases` returns whitelist). Two paths: (a) widen `_resolve_case_dir`, (b) UI pre-flight + explanation surface. Picked (b) because it's smaller blast radius, fully reversible, and surfaces the architectural truth to the user instead of hiding it.

4. **VerdictPill DRY caught a real drift**.
   - MultiCaseRibbon (V73.3, just-created) used a DIFFERENT color for PENDING than TruthChainContent (V71). V73.4 collapsing them into one primitive fixed the drift before it shipped. Two call sites that agreed in V72 would have diverged immediately without the DRY pass.

## What surprised us

1. **The 36 V72 baselines all still passed at maxDiffPixelRatio=0.01** even after V73.2 changed `text-v3-textTertiary` and V73.3 added a ~90px multi-case ribbon below the canvas at Step 5. Three possible reasons:
   - Tertiary text is small surface area; tone change affects <1% of pixels.
   - Test 29 waits for `trustgate-verdict-block` which mounts on the canvas (above the new ribbon).
   - playwright's `maxDiffPixelRatio: 0.01` (1%) tolerance is forgiving for localized changes.

   This is an honest blind spot: SSIM-based comparison would have flagged the structural change. The reverse-stop policy named SSIM but the tooling uses pixel-ratio. Carry to V74 as a methodology gap (NOT a V73 regression).

2. **The vitest contract test for AdvisorContent was implicitly relying on `useQuery` failing silently** (no QueryClientProvider). When V73.1 added `useCaseList()` the failure became visible. Lesson: tests that render components doing fetches MUST be wrapped in QueryClientProvider even if pre-V73 they didn't need to be.

3. **The CASES_IMPORTED test fixture in V73's contract test uses fields that don't match `CaseIndexEntry`** (`physics` / `difficulty` / `solver` / `tags` / `available_demo_dirs` instead of `flow_type` / `geometry_type` / `turbulence_model` / `contract_status` / `run_summary`). The test passes because the consumer only reads `case_id` and `case_kind`. This is a future fragility — if AdvisorContent ever reads another field, the tests will silently break. Note for V74: tighten test fixtures to match real types.

## What I'd do differently
