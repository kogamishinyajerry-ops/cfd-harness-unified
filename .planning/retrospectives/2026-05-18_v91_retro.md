## What went well

1. **Earliest-possible 2-consec close**. V91 hit 100/100 on iter-0 AND
   iter-1 back-to-back. The substrate landed clean on first scoring;
   no rework iterations needed. This is the best class of arc execution
   (sub-DECs land green, scorer ratifies immediately) — happens when
   pre-implementation surface scan (DEC-V61-088) accurately captures
   the change perimeter AND test-first discipline holds across all
   sub-DECs. V91 had both.

2. **JSON SSOT pattern came together cleanly**. The split — commentary
   text + provenance + severity in JSON, predicates language-native in
   TS + Python — solved the cross-language drift problem WITHOUT
   forcing logic duplication. Predicate logic is trivial enough (≤25
   LOC per rule) that maintaining lockstep across TS + Python is
   acceptable, and the parity fixture test catches any divergence
   structurally. This is a reusable pattern for V92+ (any future
   shared-text-but-language-native-logic SSOT).

3. **Byte-reproducibility preserved through additive sidecar**. The
   audit-package zip was the most fragile part of V91 (HMAC depends on
   byte-stability). Approach worked: `_zip_entries_from_manifest`
   stayed generic (just reads `manifest["commentary"]` as a dict and
   writes canonical JSON); the V9-specific logic lives in
   `manifest_adapter.py` which is purely additive. 3× `serialize_zip_bytes`
   produces SHA-256 identical bytes. Old bundles without `commentary`
   key continue to serialize correctly (backward compat).

4. **Cross-language parity test discipline scaled**. 6 fixtures × 8
   rules = 48 matched-commentary positions byte-verified across TS and
   Python. Python generated the frozen fixture; TS test verifies
   byte-equal. Either binding can be edited independently AND the
   parity test catches any divergence on next run. This is stronger
   than "two test suites in two languages doing similar things" — it's
   one shared fixture proving identical output.

5. **V78 1-vote-veto regression-class confirmation** (good as
   intelligence even though bad as scorer behavior). V90 found
   stability scorer's `100 − flake×30` is too brittle. V91 confirms
   the SAME class on ux scorer's `flow_completion = (passed/total) × 60`
   linear pro-rate. Two pillars × one root cause = strong evidence the
   V78 scorer family should evolve toward "median of N runs" or
   "majority-vote" semantics. This is the next-arc Open Q candidate.
