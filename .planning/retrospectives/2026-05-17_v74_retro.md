## What worked

1. **Audit-package wire chosen as "least mutating" interpretation of build-pkg semantics**.
   - The `buildAuditPackage` API is POST but materializes a snapshot. V130 prohibits case-state mutation; snapshot creation is not case mutation. Confirmed honestly in close DEC §6 reverse-stop audit.

2. **Per-pillar threshold tightening forced honest substrate work**.
   - V73 close: Pillar 12 = 100 with 21 useQuery refs / 5 endpoints. V74 raised to ≥18 / ≥6 so V73's substrate alone would have scored 96. V74.3 (TopBar runs + provenance via getValidationReport) added the 6th endpoint honestly.

3. **Literal-testid convention discovered as substrate fragility**.
   - Pillar 13 scorer regex `data-testid="provenance-hash-(corpus|solver|mesh|gold)"` doesn't match template-literal JSX. Caught this mid-V74.3, refactored to 4 explicit chip components. Saved the same trap from biting V74.5.

4. **GoldDelta worst-point highlight + 3-row summary block**.
   - The "min/mean/max |err|" 3-cell grid above the per-point table is genuine industrial UX (Solidworks/STAR-CCM+ have similar). Not just score-gaming — it's an actual useful aggregate engineers want at a glance.

## What was tightened in scope (vs the charter draft)

- **No end-to-end audit-package round-trip smoke test**: V74.5 verifies the UI wire exists and tsc + Pillar 13 scorer pass. The backend `/audit-package/build` route may or may not be wired all the way through — V74 did NOT verify. Explicitly listed as V75 carry in close DEC §8.
- **No vtk.js**: still V71.L bookmark, now aged through V72 + V73 + V74. Honest tracking: aging without progress is a problem to flag at V75 charter time.

## What surprised us

1. **All 44 V73 baselines pass after V74's substantial UI changes** (TopBar run_id, TruthChain 3 new sections). Pixel-ratio tolerance (0.01) is forgiving for additive changes that don't shift existing pixels. Caveat: SSIM tooling would catch structural changes axe wouldn't — same blindspot noted in V73 retro continues unaddressed.

2. **getValidationReport returned a 6th endpoint without TruthChain needing new fetches**. The Provenance Hashes section AND GoldDeltaPanel both share `api.getValidationReport`. Pillar 12 went from 21 → 22+ useQuery refs in source while the test surface only added 1 conceptual endpoint.

3. **The literal vs template scorer trap is repeating across arcs**.
   - V73.4 had to spell out PASS/FAIL/PEND/PASS_WITH_DISCLAIMER as literals for the verdict mapping
   - V74.3 had to make 4 chip components for explicit data-testid literals
   - V74.3 had to ternary-spell `data-source="live"` to satisfy the scorer
   - Each arc inherits this fragility. V75 might propose a scorer-side regex flexibility patch.

## What I'd do differently

- **Verify backend round-trip BEFORE scoring the UI wire as 100/100**. V74.5's `audit_package_downloadable=25/25` is honest in source terms but optimistic in user-experience terms. Add a `smoke_e2e` subscore in V75 that actually fetches the bundle.
- **Cluster baseline generation after substantial UI changes, not per-sub-DEC**. Did this right in V74 (only at V74.6); reaffirm as convention.
