## What went well

1. **BY-CONSTRUCTION V130 discipline was achievable**. The V9 design space
   (pattern-matching advisor with human-curated rules + pure-function
   matcher + pure-presentational surface) means V130 isn't a runtime
   discipline you have to keep enforcing — it's a structural property of
   the code. The contract test reads the source and asserts the surface
   CAN'T mount a fetch / can't use useEffect / can't import api/client.
   This is a one-way ratchet UP from V83-V89's runtime+sandwich proofs.

2. **3-layer purity stack came together cleanly**:
   - V9.C: pure data (8 rules · zero side effects · zero imports of
     stateful code)
   - V9.B: pure function `(slice, rules) → matches[]` with try/catch around
     each predicate for graceful degrade (1 buggy rule cannot break the
     other 7)
   - V9.A: pure presentational React (no hooks beyond useMemo·useState for
     pure derived UI state; no useEffect at all)
   This stack made the contract test surface tiny — 26 + 13 = 39 tests
   covered every contract behavior including determinism and graceful
   degrade, with no mocking needed (pure functions are trivially testable).

3. **Adapter pattern (`adaptBridgeArtifactToSlice`) gracefully bridged
   shape mismatch**. V9.B's `RunArtifactSlice` expects history-array
   residuals (`residuals.p[]`) but the existing BridgeArtifact only carries
   single-value snapshots. Rather than retro-extending BridgeArtifact (high
   blast radius · couples V9 to backend changes), the adapter returns
   `undefined` for history-dependent fields. Predicates that depend on
   `residuals.p[]` simply don't fire — matcher reports 0 matches for those
   rules — which is correct behavior (we genuinely don't have the data to
   judge). Forward-plan V91+ can either widen BridgeArtifact OR widen the
   adapter — V90 doesn't lock that choice in.

4. **Cohort-pattern recognition (V86/V87/V88/V89/V90) refined the
   taxonomy**. Initially observed as 2-state ("verbatim → substantiate"
   OR "verbatim → next LAND"); V90 confirmed the actual rule is
   **"verbatim AFTER LAND-then-substantiate = next LAND"** rather than a
   degenerate "substantiate-of-substantiate" loop. This is a concrete
   pattern signal for V91+ — when the next "CFD能力" verbatim arrives, look
   at the previous arc's class to predict.

5. **Statistical-flake disposition discipline kept 13-arc streak alive.**
   iter-1's stability=70 was the FIRST close-attempt break in the V79→V90
   no-scoring-change streak; instead of folding ("the streak is broken!")
   we treated it like V89's #77 flake: diagnose (9 isolation runs · all
   PASS · 1-in-9 = 11% flake rate consistent with `npm run test` known
   nondeterminism on this stack), document with evidence, run iter-3.
   Outcome: 2-consec gate MET on iter-2 + iter-3 anyway.

## What didn't go well (or could be sharper)

1. **Iter-1 cost an iteration we didn't need.** Close took 4 iterations
   (0/1/2/3) for what should have been 2-3. Root cause = V78 stability
   scorer's `100 − flake×30` formula treats any single flaky vitest
   subrun as −30 points, which is a 1-vote veto for a 1-in-N statistical
   noise event. With 13-arc streak data we now have, this is consistently
   costing us 1 extra iteration per arc (or per 2 arcs). **Open Q
   carried** to V91 close DEC: should V78 scorer change to 2-of-3-must-pass
   (vote-based) instead of "any-fail = −30"? Decision: defer until next
   real scoring-evolution arc (changing scorer breaks streak target).

2. **V90 iter-0 first-run was 86 (visualization baseline #29 flake).** Same
   class of statistical flake as iter-1 stability but caught early
   (re-ran iter-0 to get 100). Net effect: 1 extra `score_all.sh` invocation
   pre-iter-1, which costs ~3 min wall time. Acceptable but tracks the
   same Open Q #1 — V78 is increasingly noise-sensitive.

3. **V9.D was DEFERRED to V91+** rather than landed in V90. This is fine
   (V90 sub-DEC density was sufficient) but means the AFTER-RUN axis is
   still partially open until V9.D lands. Forward-plan documented; no
   surprise.

4. **`adaptBridgeArtifactToSlice` is a graceful-degrade WORKAROUND, not a
   solution.** Currently no rule that depends on history-array residuals
   actually fires for real runs because the data isn't carried in
   BridgeArtifact. V9 still produces value (the rules that depend on
   `convergence_stats`, `gold_delta`, `forces` fire correctly) — but
   3-of-8 rules are dormant in production until either BridgeArtifact
   widens or a new sidecar emits history arrays. Track for V91+.
