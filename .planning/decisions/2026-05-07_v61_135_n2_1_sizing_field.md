# DEC-V61-135 · N2.1 MeshSizingField

## What changed

A new **structured per-job sizing field** is exposed alongside the existing
mesh_mode preset radio:

```
sizing:
  base_lc: 0.05               # gmsh nominal lc
  min_lc: 0.005               # CharacteristicLengthMin
  max_lc: 0.10                # CharacteristicLengthMax
  curvature_target_size: 20   # MeshSizeFromCurvature
  proximity_layers: 4         # MeshSizeExtendFromBoundary (1..10)
```

All fields optional. Setting any one switches gmsh away from the
preset/target derivation and labels the response `mesh_mode_used: "custom"`.
Cell-budget hard cap (50M) still applies.

### Backend

- New `ui/backend/schemas/mesh_sizing.py` (`MeshSizingField` Pydantic with
  positivity + ordering validators, `is_active()` helper)
- `MeshRequest.sizing_field: MeshSizingField | None` added; back-compat
  preserved (omitting the field = current behavior)
- `MeshMode` literal extended with `"custom"`
- `mesh_imported_case` and `run_gmsh_on_imported_case` accept the new
  `sizing_field` kwarg; pipeline passes it through
- `_gmsh_inline` branches on `sizing_field`: when active, sets
  `Mesh.CharacteristicLengthMin/Max` from min/max (or base ± defaults),
  sets `Mesh.MeshSizeFromCurvature`, enables
  `Mesh.MeshSizeFromBoundary` + `Mesh.MeshSizeExtendFromBoundary` from
  proximity_layers
- Sizing field crosses the multiprocessing boundary as a plain dict
  (`sizing_field.model_dump()`) to avoid spawn-time pydantic re-imports

### Frontend

- `MeshSizingField` interface + `MeshRequestMode` literal added to
  `types/mesh_imported.ts`
- `api.meshImported(caseId, mode, sizingField?)` — third optional arg;
  client strips the body field when no values are set
- `Step2Mesh.tsx` adds a `<details>`-collapsed "Advanced sizing
  (override preset)" panel with five `<input type="number">` fields,
  reset-to-preset button, and inline ordering validation (min ≤ base ≤ max)
- `MeshWizardPage` and `Step2Mesh` switch their radio state to
  `MeshRequestMode` (the narrower request literal)
