## 3. Decisions

### 3.1 V92 sediment — `cellZoneInside inside` topology heterogeneity

`cellZoneInside inside` ray-cast works for simple-topology STLs (single watertight outer shell) but fails for complex-internal-void STLs (`fuse_many` union of plates+fins with internal channel-surface shells). v5 attempt validated both halves: cold went 3% → 115%, solid went 37% → 0% under identical dict syntax. Root cause: ray-cast parity changes meaning when STL has internal void surfaces (channels). v5b reverts solid to insidePoint walk (37% retention, V85-family connected-component cap but populated); keeps cold at `inside` (115% retention). The hybrid strategy is empirically optimal given the STL topology constraints. Cross-case validator (`cellZoneInside_validator` under M-A8) deferred to N≥2 case (case_002b candidate). CAD-side fix (`envelope.cut(channels)` instead of `fuse_many(plates+fins)`) registered as harvest-003 follow-up.

V92 is the **third orthogonal failure mode** in case_011's dict-orchestration family (V85 = solid insidePoint coordinate in wrong material; V89 = fluid insidePoint coordinate in fin space; V90 = modern locationsInMesh syntax for separate-STL; V92 = `cellZoneInside inside` for complex-void STL). All four share the same engineering symptom (sHM accepts dict + produces mesh + some cellZone has 0 cells silently) but address ORTHOGONAL defects.

### 3.3 chtMultiRegionSimpleFoam e2e run on v5b mesh — PASS

The v5b mesh has all 3 regions present. Solver dependencies discovered + addressed:
- T BC files needed `_to_domain.*` catch-all (added to hot, cold, solid T)
- Solid region needed `0/region_solid/p` (created per OF 2312 chtMultiRegionSimpleFoam cpuCabinet tutorial precedent — heSolidThermo path internally allocates p reference even for incompressible solid)
- Solid region needed SIMPLE block in `system/region_solid/fvSolution` (scaffold emitted PIMPLE only for chtMultiRegionFoam compatibility; chtMultiRegionSimpleFoam wants SIMPLE)
- chtMultiRegionFoam → chtMultiRegionSimpleFoam (steady CHT-multi-stream variant in OF 2312; the scaffold script emitted PIMPLE block for chtMultiRegionFoam which uses unified PIMPLE-or-steady mode, but chtMultiRegionSimpleFoam directly requires SIMPLE)

After fixes: chtMultiRegionSimpleFoam ran **200 SIMPLE iter without FATAL**, stopped at user request after meeting ≥200 threshold.

**V94 caveat (physics degenerate)**: case_011 STL files lack labeled inlet/outlet face-zones → mesh has no flow-boundary patches → solver ran a degenerate pure-conduction problem. All three regions equilibrate toward the ~360 K conduction midpoint (between initial hot 420 K and cold 300 K), NOT the Kays-London predicted T_h_out=364 K + T_c_out=350 K convective outlet temperatures. This is a substrate defect, not a solver defect — the harness demonstrates chtMR-SimpleFoam works for 3-region CHT-multi-stream procedurally, but case_011 substrate needs a CAD-side or post-mesh createPatch fix (V94) to recover the intended convective regime.
