# DEC-V61-196 · B-ext-6.1 · F15 fix

## Status

**Accepted 2026-05-07** — first sub-DEC under B-ext-6 charter.
Closes both layers of F15 (path mismatch + scalar-only parser) and

`submit_drop`. Charter top-line goal **achieved**.

## Root cause refresher

F15 (DEC-V61-194) had two layers:

1. **Path mismatch** —
   `ui/backend/services/render/field_sample.py::_resolve_field_path`
   looks for `<case_dir>/<run_id>/<name>`, but
   - F11's `write_run_artifacts` puts run dirs under
     `reports/<case_id>/runs/<run_id>/` (containing measurement.yaml)
   - OpenFOAM writes time-step output under `<case_dir>/0/`,
     `<case_dir>/0.5/`, `<case_dir>/<final_time>/`
   - Neither layout intersects with `<case_dir>/<run_id>/`
2. **Scalar-only parser** — `_parse_internal_scalar_field` only
   handles `nonuniform List<scalar>`. The U field is `nonuniform
   List<vector>` (3-component per cell), which would map to
   `field_unsupported` 422 even with the path fixed.

## Fix layer 1 — post-solve symlink

`ui/backend/routes/case_solve.py::solve` now creates a symlink
`<case_dir>/<run_id>` → `<final_time_dir_name>` after
`run_icofoam` succeeds and `run_id` is generated.

```python
try:
    if result.time_directories:
        final_time_name = result.time_directories[-1]
        target = case_dir / final_time_name
        link = case_dir / run_id
        if target.is_dir() and not link.exists():
            link.symlink_to(final_time_name, target_is_directory=True)
except OSError:
    pass
```

Best-effort: any FS that doesn't support symlinks falls back to the
prior 404 behavior; never fails the /solve response. The route's
existing path-traversal containment guard (line 141+ in
field_sample.py) still passes since the symlink target is within
IMPORTED_DIR.

## Fix layer 2 — vector field parser

`ui/backend/services/render/field_sample.py`:

1. New regex `_INTERNAL_NONUNIFORM_VECTOR_RE` matches
   `internalField nonuniform List<vector> <count>(<triples>);`.
2. New regex `_VECTOR_TRIPLE_RE` extracts each `(vx vy vz)` from
   the body.
3. New parser `_parse_internal_vector_field(field_path)` returns a
   flat float32 array of length `3 * cell_count` in
   (vx, vy, vz, vx, vy, vz, ...) order.
4. New constant `_VECTOR_FIELD_NAMES = {"U", "Uavg", "U.air",
   "U.water"}` and helper `_is_vector_field(name)`.
5. `FieldSampleResult` gains `components_per_cell: int = 1`.
6. `build_field_payload` dispatches to the vector parser when
   `_is_vector_field(name)`. Cache hit/miss both populate
   `components_per_cell` correctly.

## Route header

`ui/backend/routes/geometry_render.py`: the field route now emits
`X-Field-Components: 1` (scalar) or `3` (vector). Frontend +
persona-side post-processing both consume this to split the binary
blob into the right shape. `Content-Length = 4 *
point_count * components_per_cell`.

## What's still missing for a real-physics verdict pass

The persona submitted observed=0.0 because **U field alone is
insufficient** to compute reattachment length. The reattachment
metric needs:

1. U field (now available via /field/U after F15 fix) ✓
2. **Cell centers** (Cx, Cy, Cz) — NOT written by default by simpleFoam
   / icoFoam. Requires `postProcess -func writeCellCentres -time
   <final_time>` invocation in the same Docker container.
3. **Lower-wall identification** — knowing which cells are adjacent
   to y=0 wall in backward-step coordinate frame.

Path to real verdict pass:
- B-ext-6.2 (planned, NOT done in this DEC): post-solve
  `writeCellCentres` hook + add Cx/Cy/Cz to `_VECTOR_FIELD_NAMES`-style
  scalar handling so /field/Cx works.
- B-ext-6.3: client-side reattachment scan in the rehearsal driver
  (or persona itself).

Even with cell centers, LDC defaults on backward_step won't produce a
correct L/h ≈ 6.0 — that needs **B-ext-7 real-physics path**
(from_stl_patches=1 + correct simpleFoam/kOmegaSST + named patches).
