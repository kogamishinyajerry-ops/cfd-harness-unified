## V130 BY-CONSTRUCTION extension to backend (V91 contribution)

V90 established literal-source LLM-absence as the strongest V130 class
on the frontend. V91 extends this to the backend matcher:

1. **Module import allowlist** (RS#35) · Python AST scan asserts
   `pattern_matcher.py` + `rules.py` + `manifest_adapter.py` import
   ONLY: `__future__`, `math`, `json`, `dataclasses`, `typing`,
   `pathlib`, `re`. No `requests`, `urllib`, `httpx`, `aiohttp`,
   `subprocess`, `os.system`, `openai`, `anthropic`. The Python matcher
   is architecturally incapable of making a network call · `claude_p`
   subprocess · or external API request.
2. **Pure function over dict argument** · `derive_slice_from_manifest`
   reads ONLY the manifest dict passed in; no filesystem traversal · no
   environment-variable read. Same input → same output, always.
3. **JSON SSOT shared with TS** (RS#37) · the corpus is canonical
   (sorted keys + indent=2 + UTF-8 + trailing newline) AND byte-loaded
   by both bindings. Drift between TS and Python text is structurally
   prevented (you'd have to edit two places consistently AND the parity
   fixture validation catches if you only edit one).
4. **Cross-language parity** (RS#38) · 6 frozen fixtures × 8 rules = 48
   matched-commentary positions verified byte-identical in TS + Python.

V130 now has **7 layers of defense** (V83-V91), all complementary:
1. Lexical denylist (V83.1)
2. Structural fetch-zero at mount (V83.2)
3. Architectural V132=9 mutating-route lock (V84)
4. Live browser confirmation (V85+ sandwich)
5. Env-gated visualization-only injection (V89.2)
6. Literal-source LLM-import absence (V90)
7. **NEW: Python module-import allowlist + JSON SSOT byte-pinning (V91)**
