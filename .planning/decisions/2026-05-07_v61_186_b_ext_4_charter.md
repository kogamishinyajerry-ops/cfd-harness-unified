## Three findings to close

### Finding 1: persona mesh-cycle pathology (B-ext-4.1)

R7 cell 1 (naca0012/experienced_fluent): persona executed 4× /mesh
+ 2× /setup-bc + 0× /solve over 63 turns. Each /mesh erased prior
/setup-bc work (Fix 2 from V61-182 working as designed). Persona
kept regenerating mesh trying to "fix" perceived issues in
patch-classification or face-index responses, never advancing to
/solve.

**Fix**: add explicit Step 2 warning in all 3 persona prompts:

> /mesh is DESTRUCTIVE. POST it ONCE at the start of Step 2.
> NEVER POST /mesh again after /setup-bc (Step 4) — doing so
> erases your BC files. If /face-index or /patch-classification
> shows something unexpected, fix it via PUT (don't re-mesh).

### Finding 2: F11 — /run-history empty after successful /solve (B-ext-4.2)

```bash
GET /api/cases/<case_id>/run-history → 200 {"runs": []}
```

Run registry not populated by /solve. Step 6 prompts route persona
through /run-history for run_id discovery, then to
/results/{run_id}/field/{name}. Without populated runs, that fetch
path is broken.

**Fix**: investigate the run-history route + run_icofoam contract;
populate the registry on successful /solve. Add regression test.

### Finding 3: F12 — LDC defaults produce NaN U field on non-cube geometry (B-ext-4.3)

```bash
GET /api/cases/<case_id>/results-summary
  → 422 results_malformed: U field contains 1584 NaN/Inf entries
```

LDC default mode (`from_stl_patches=0`) writes lid_velocity=(1,0,0),
nu=1e-3, Re=100, BC patches `lid` (top of bbox) + `fixedWalls`. On
NACA0012 the "lid" patch is just whatever face is on +y of the
bbox — not airfoil-physics-meaningful.

**Fix two-pronged**:
1. Persona prompt: stronger Step 4 guidance — for non-cube geometry
   ALWAYS use `from_stl_patches=1` with case-physics bc_contract
   (Re from brief, ν from brief, inlet/outlet/wall classification)
2. Workbench: warning header when LDC fall-through is invoked on
   non-cube geometry (engineer-detectable signal that bc_kind=ldc
   is wrong for this STL)
