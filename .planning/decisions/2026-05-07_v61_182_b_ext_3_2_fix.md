# DEC-V61-182 · B-Ext-3.2 F10 fix

## Status

**Accepted 2026-05-07** — two-pronged workbench-side fix per
DEC-V61-181 root-cause analysis. Surface the inconsistency loudly
(Fix 1) and prevent it ergonomically (Fix 2).

## Fix 1 — pre-flight mesh-BC consistency check in `run_icofoam`

`ui/backend/services/case_solve/solver_runner.py` adds:

- `_scan_top_level_block_names(body: str) -> list[str]` — brace-depth-
  aware OpenFOAM dict body scanner that returns ordered top-level
  block names.
- `_read_polymesh_patch_names(case_host_dir: Path) -> list[str]` — parses
  `constant/polyMesh/boundary`, returns ordered patch names. Trailing
  `// ******` comments after `)` are tolerated.
- `_read_bc_field_patch_names(field_path: Path) -> list[str]` — parses a
  `0/<field>` file's `boundaryField` block, returns ordered patch keys.
- `_check_mesh_bc_consistency(case_host_dir: Path) -> str | None` —
  validates each `0/<field>` `boundaryField` references only patches
  present in `polyMesh/boundary`. Returns `mesh_bc_mismatch:` error
  string on first mismatch; `None` if consistent or files missing.

`run_icofoam` calls `_check_mesh_bc_consistency` immediately after
the controlDict check. On mismatch, raises `SolverRunError` carrying
the `mesh_bc_mismatch:` message. The route handler in `case_solve.py`
maps this prefix to **HTTP 409** with `failing_check="mesh_bc_mismatch"`,
distinguishing from the existing `bc_not_setup` (no setup-bc run yet)
and `solver_diverged` (BCs OK but solver failed).

Error message format:
```
mesh_bc_mismatch: 0/p references patches ['lid', 'fixedWalls'] but
constant/polyMesh/boundary only has ['patch0']. The mesh was likely
regenerated after setup-bc; re-run /api/import/{case_id}/setup-bc
to align BC files with the current mesh patches.
```

This converts a cryptic OpenFOAM `Cannot find patchField entry for
patch0` into an actionable 409 with explicit remediation.

## Fix 2 — eager invalidation in `mesh_imported_case`

`ui/backend/services/meshing_gmsh/pipeline.py` adds
`_invalidate_stale_bc_after_mesh_regen(case_dir)` called at the end
of `mesh_imported_case` after a successful gmshToFoam.

Behavior:

1. Remove `case_dir/0` and `case_dir/0.orig` directories (rmtree;
   best-effort, ignores OSError so Fix 1 can still surface the
   inconsistency if rmtree fails).
2. Read `case_manifest.yaml`, remove `overrides.raw_dict_files`
   entries whose key starts with `0/`, write back. Silently skips
   if manifest is missing or unparseable (Fix 1 is the load-bearing
   guard; Fix 2 is ergonomic cleanup).

Effect: after a successful POST /mesh, the case has a fresh polyMesh
+ no BC files. The next POST /setup-bc authors BC files from scratch
matching the new mesh patches. No stale state can leak through.
