# DEC-V61-137 · N2.3 Prism Layer (snappyHexMesh addLayers)

## Decision

Add a NEW POST endpoint `/api/import/{case_id}/mesh/prism-layers` that
runs snappyHexMesh's addLayers stage on the existing polyMesh produced
by the gmsh stage. Engineer supplies a single-patch prism config (v0
cap; multi-patch deferred to N2.3-extend). The route mutates
constant/polyMesh in place and is registered in V132
`MUTATING_ROUTES` + `KNOWN_MUTATION_FUNCTIONS` so AI dispatch paths
cannot call it.

## Scope

### Backend (~720 LOC)

- **New schema** `ui/backend/schemas/mesh_prism_layers.py`:
  - `PatchPrismConfig` (patch + first_cell_height + expansion_ratio
    + num_layers) with positivity / range / charset validators
  - `MeshPrismLayersRequest` with v0 single-patch cap (multi-patch
    enforced absent at schema layer)
  - `PrismFailingCheck` literal: case_not_found · polyMesh_not_ready
    · patch_not_found · snappy_diverged ·
    snappy_addlayers_did_not_converge · snappy_container_failed
- **New service** `ui/backend/services/meshing_snappy/`:
  - `addlayers_renderer.py` — minimal `system/snappyHexMeshDict`
    template: castellatedMesh false / snap false / addLayers true.
    Per-patch layer block with nSurfaceLayers, firstLayerThickness,
    expansionRatio, minThickness (= first_cell_height * 0.5).
    Float rendering uses fixed-point [1e-3, 1e6) and scientific
    elsewhere for legibility (small first_cell_heights ~1e-4
    common).
  - `snappy_runner.py` — docker SDK pattern mirrored from
    `to_foam.py`: retag tarball entries to container UID/GID, push
    case dir, exec `snappyHexMesh -overwrite`, pull log + refreshed
    polyMesh, atomic-ish swap on host (rename current polyMesh →
    .prev → move new in → drop .prev). Surfaces `SnappyAddLayersError`
    (user-input fault) vs `SnappyContainerError` (deployment fault)
    distinctly. Verifies polyMesh exists + patch name in boundary
    BEFORE the docker round-trip. Parses addLayers log for
    `layers_added` + `coverage_fraction` (best-effort regex; degrades
    summary, doesn't fail the run).
  - `pipeline.py` — `apply_prism_layers(case_id, patches=...)`
    dispatching `SnappyAddLayersError` message → `failing_check`
    enum (polyMesh_not_ready / patch_not_found /
    snappy_addlayers_did_not_converge / snappy_diverged) and
    `SnappyContainerError` → snappy_container_failed.
- **New route** `ui/backend/routes/mesh_prism_layers.py`:
  POST `/import/{case_id}/mesh/prism-layers` with status mapping
  (404 / 422 / 502).
- **V132 registry update** `ui/backend/services/ai_actions/mutating_routes.py`:
  - `MUTATING_ROUTES` += `("POST", "/api/import/{case_id}/mesh/prism-layers")`
  - `KNOWN_MUTATION_FUNCTIONS` += `apply_prism_layers` registered at
    both module path forms (pipeline + service `__init__`)
- **main.py wiring** with same optional-import discipline as
  `mesh_imported`.

### Frontend (~360 LOC)

- **New types** `types/mesh_prism_layers.ts` mirroring backend schema
  + bound constants
- **New api fn** `meshPrismLayers(caseId, patches)` posting to the
  new endpoint with full ApiError + structured rejection handling
- **Step2Mesh.tsx** new collapsed `<details>` "Boundary layers ·
  prism" panel:
  - Form inputs: patch (text) · first_cell_height · expansion_ratio
    · num_layers (integer)
  - "Apply prism layers" button (NOT bound to [AI 处理] action —
    explicit engineer-driven additive step; disabled until a mesh
    has been generated)
  - Success/rejection/error sub-panels with REJECTION_HINTS for
    each new failing_check
  - `PrismFieldInput` component using same draft-state pattern
    introduced in N2.2 R2 (string draft + commit-on-finite-parse
    + drop-on-blur)

### Tests (~700 LOC backend + ~250 LOC frontend)

  snappy_runner helpers (boundary patch name parse, addLayers log

## Risk

**Class**: **HIGH** (per N2 charter §3 risk column).

**Why**:
1. Introduces a NEW mutating endpoint → V132 contract surface
   migration. If `MUTATING_ROUTES` / `KNOWN_MUTATION_FUNCTIONS` were
   missed, AI dispatch paths could silently call `apply_prism_layers`,
   violating V130 advisor-only contract.
2. New container exec path (snappyHexMesh) — different binary,
   different success/failure modes, different log format from
   `gmshToFoam`.
3. snappyHexMesh notoriously fragile near sharp geometry / high
   non-orthogonality (V129a per-patch chip data territory).
4. Atomic-ish polyMesh swap on host has a race window if a
   concurrent solver reads polyMesh during the rename. Acceptable
   in current single-engineer flow but worth noting.

**Mitigations**:
1. **V132 registry**: explicit dual entry (HTTP route + Python
   symbol both forms) + explicit dedicated tests
   (`test_prism_route_is_in_mutating_routes_registry`,
   `test_apply_prism_layers_is_in_known_mutation_functions`,
   `test_is_mutating_route_recognizes_prism_endpoint`). The
   existing V132 Layer-A test asserts AI dispatch paths cannot
   bind any KNOWN_MUTATION_FUNCTIONS entry.
2. **Container exec separation**: `services/meshing_snappy/` is
   parallel to `meshing_gmsh/` and duplicates the docker pattern
   (~150 LOC) instead of extracting a shared helper. Mirrors the
   `to_foam.py` rationale: small + self-contained beats wrong
   abstraction.
3. **Pre-checks before container round-trip**: polyMesh existence
   + patch name in boundary verified on the host; failure is
   `polyMesh_not_ready` / `patch_not_found` (422 with structured
   reason) instead of a 30-second snappyHexMesh container run
   ending in opaque exit_code=1.
4. **Atomic-ish swap**: rename current polyMesh → polyMesh.prev,
   move new tree in, drop .prev. Failure mid-rename leaves the host
   with `.prev` polyMesh that the engineer can recover manually.
5. **No-layer-actually-added detection**: parsed log shows
   layers_added=0 → raise `snappy_addlayers_did_not_converge` (422)
   even if exit_code=0. Avoids deceptive "prism layers applied"
   responses with zero physical effect.
6. **Single-patch v0**: cap multi-patch interaction explicitly at
   schema layer; multi-patch + per-patch quality knobs deferred to
   N2.3-extend so the V132 contract surface lands narrow first.

## Out of scope (deferred)

- **Multi-patch prism config**: schema is list-shaped; v0 caps to 1.
  N2.3-extend lifts the cap.
- **Per-patch quality controls** (custom maxNonOrtho /
  featureAngle / nLayerIter overrides): use template defaults for
  v0; engineer needing custom controls can edit the rendered
  `system/snappyHexMeshDict` via the V096 RawDict editor and
  re-run via direct OpenFOAM CLI.
- **Castellated + snap stages**: explicitly false in the rendered
  dict. Full snappyHexMesh workflow is out of scope; this DEC is
  scoped to addLayers-only on top of gmsh-produced polyMesh.
- **AI advisor for prism config**: N6 territory. v0 is form-driven;
  N6 will surface read-only suggested values with copy-paste
  application (per V130 advisory contract).
- **Solver kick-off after prism**: N4 / Step 4 territory; this DEC
  refreshes the mesh only.
