## F9 — `0.orig` ValueError in post-solve scanner

`solver_runner.py:471` did `tuple(sorted(pulled, key=lambda s:
float(s)))` on the list of pulled time directories. The `ls -d
[0-9]*` glob in container.exec_run matches `0.orig` (the BC backup
dir setup-bc creates). `float("0.orig")` raised ValueError.

### Fix

Extracted helper `_filter_numeric_time_dirs()` that drops any
non-float-parseable name:

```python
def _filter_numeric_time_dirs(time_dirs: list[str]) -> list[str]:
    out: list[str] = []
    for td in time_dirs:
        try:
            float(td)
        except ValueError:
            continue
        out.append(td)
    return out
```

Defensive against `.orig`, `.bak`, and arbitrary non-numeric
suffixes. Preserves scientific notation (`1e-05`).

### Tests

Added 3 regression tests in `test_solver_runner_convergence.py`:

- `test_filter_numeric_time_dirs_drops_setup_bc_backup` — drops `0.orig`
- `test_filter_numeric_time_dirs_drops_other_non_numeric_suffixes` — drops arbitrary names
- `test_filter_numeric_time_dirs_preserves_scientific_notation` — keeps `1e-05`

15/15 solver_runner tests pass.

## F10 — BC patch-name mismatch (escalate to B-ext-3)

`POST /solve` consistently returns 502 with body:

```json
{"detail":{"failing_check":"solver_diverged","detail":
"simpleFoam exited with code 1; see ... log.icoFoam ..."}}
```

Solver log root cause:

```
--> FOAM FATAL IO ERROR:
Cannot find patchField entry for patch0
file: /tmp/.../<case>/0/p/boundaryField from line 6 to line 7.
```

`setup-bc` writes `0/p/boundaryField` keyed by `patch0`, `patch1`,
…, but the actual mesh `polyMesh/boundary` (after the F7 patch-split
workflow stamps it) uses semantic names (`inlet`, `outlet`, `wall`).
The boundary-field contract is broken between setup-bc and the
mesh.

This is **workbench-side**, not a persona-prompt issue. Persona
correctly drove Steps 1-4 (all 200), exercised the F7 patch-split
flow, but Step 5 is gated on a setup-bc artifact that the solver
rejects.

### Reproduction

```bash
# After a successful Steps 1-4 sequence:
curl -sX POST -H "Content-Type: application/json" -d '{}' \
  http://localhost:8000/api/import/<case_id>/solve
# → 502 with solver_diverged + log.icoFoam shows patch0 not found
```

### B-ext-3 candidate fixes

1. setup-bc reads the actual mesh boundary patch names from
   `polyMesh/boundary` and emits matching keys in
   `0/p/boundaryField` / `0/U/boundaryField` / `0/k`, `0/omega`
   etc.
2. Or: solver-call layer remaps engineer-supplied semantic names
   to mesh-emitted indices before invoking OpenFOAM.
3. Add an integration test: full Steps 1-5 sequence on each charter
   case must produce /solve POST 200 with `converged` field.
