## 3. What changed

### Source: `ui/backend/services/geometry_ingest/shm_dict_validator.py`

**New module-level constants** (V99):

- `_CONSTRAINED_PATCH_TYPES: frozenset[str]` —
  `{symmetryPlane, wedge, empty, cyclic, cyclicAMI}`. The patchInfo
  type values that mathematically demand single-normal source surfaces.
  Drawn from the V99 row "Cross-application" lesson: same failure mode
  applies to wedge (single planar face + axis intersection), empty
  (single face perpendicular to flat-2D direction), cyclic / cyclicAMI
  (matched pair of identical-normal patches).
- `_COLINEAR_DEVIATION_MAX: float = 0.05` — max `1 - |dot(ref, n_i)|`
  allowed before face normals are flagged as multi-normal. 0.05 ≈ ~18°
  of orientation slack — loose enough for tessellation rounding (sub-
  degree noise on a planar STL), tight enough to catch case_003 v2's
  0.556 deviation (well over an order of magnitude above tolerance).

**New helper functions** (V99):

- `_max_normal_deviation(normals)` — pure-stdlib (math.sqrt only)
  computation of the max `1 - |dot(ref, n_i)|` across L2-normalized
  face normals. Returns `None` if fewer than two non-zero-length
  normals are present (single face / empty list trivially colinear).
  Uses `abs()` on the dot product so anti-parallel normals on the same
  plane are accepted as planar (closed-shell STLs can mix face
  orientations; cf. the V99 case_003 v2 evidence).
- `_suggestion_for_constrained_patch(patch_type, surf_name)` — builds
  the V99 downgrade suggestion text. symmetryPlane → "downgrade to
  type patch + slip BC" (the case_003 v2 workaround actually applied
  in session 6); wedge / empty → "ensure STL is single planar face";
  cyclic / cyclicAMI → "ensure paired patches share identical
  normals".

**New optional kw-only arg** (V99): `validate_shm_dict()` gains
`stl_face_normals: dict[str, list[tuple[float, float, float]]] | None
= None`. The advisor still does **not** read STL files (per A4 sibling
pattern · keeps A8 OpenFOAM-utility-free + unit-testable in CI). The
caller is responsible for STL face-normal extraction (typically via
trimesh / numpy-stl) and supplies a `patch_name → list[(nx, ny, nz)]`
mapping. When `stl_face_normals is None` (default), Path (e) is a
no-op — behaviorally identical to the pre-widening advisor.

**New detection logic** — Path (e) V99 cross-check:

```
for surf_name, surf_cfg in refinementSurfaces.items():
    patch_type = surf_cfg["patchInfo"]["type"]
    if patch_type in _CONSTRAINED_PATCH_TYPES:
        normals = stl_face_normals.get(surf_name)
        if normals and _max_normal_deviation(normals) > _COLINEAR_DEVIATION_MAX:
            emit critical multi_normal_constrained_patch finding
```

**New detection logic** — Path (f) V100 type-guard:

```
def validate_shm_dict(parsed_dict, *, available_emeshes=None, stl_face_normals=None):
    if not isinstance(parsed_dict, dict):
        raise TypeError(
            f"validate_shm_dict expects a parsed dict[str, Any]; got "
            f"{type(parsed_dict).__name__}. Pre-parse OpenFOAM dict "
            "files with `PyFoam.RunDictionary.ParsedParameterFile(...)`"
            ".getValueDict() or `foamDictionary -value -entry ROOT "
            "<path>` and pass the resulting dict in. The advisor is a "
            "pure dict consumer by design (see module docstring) and "
            "does not do file IO."
        )
```

Inserted before any `.get()` call so the AttributeError-deep-in-walker
failure mode is structurally impossible.

**Finding code added**: `multi_normal_constrained_patch` (severity
critical; sits alongside the existing V52/V86 codes documented in the
`ShmFinding.code` comment).
