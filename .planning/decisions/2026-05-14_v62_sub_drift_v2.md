# DEC-V62-A-sub-M-DRIFT-V2 · runtime V-series drift guard

## Status

**Accepted 2026-05-14** — first Tier 2 milestone in V62-A. Lands one new
service module (`ui/backend/services/v_series_drift_guard.py`), patches
the `POST /ai-review` route with a 2.5-step drift enforcement hop, and
adds an 8-test file covering load / hit / partial-miss / full-miss /
audit-mode / strict-mode / route-integration / 4Q-gate. confidence: med.

## Goal

Push the V61-198 M-DRIFT v1 invariant from **commit time** to **route
time**. v1 enforces "methodology master + runtime advisor copy must be
staged together"; v2 enforces "every Finding returned by the
`/api/ai-review` route must cite V-rows that actually exist in the
runtime corpus". The residual failure mode v2 closes:

> A commit edits `advisor_stack._V_ROWS_PER_ADVISOR` to add a literal
> `"V101"` to advisor A8 without touching the methodology file. v1 sees
> nothing to enforce (master not staged), passes. The route ships a
> Finding citing V101 — a row that does not exist anywhere. Audit trail
> drift undetected.

After v2, that same Finding produces an `advisor_calls` entry
`{advisor_name: v_series_drift_guard, output.check_status:
drift_detected, output.missing_v_rows: ["V101"]}`. In `audit` mode
(default) the Finding still ships — wire contract unchanged. In
`strict` mode (`?drift_mode=strict`) the Finding is dropped before
serialization.

## Scope

### What this sub-DEC adds

- New service module `ui/backend/services/v_series_drift_guard.py`:
  - `load_v_series_index(corpus_path: Path | None = None) -> set[str]` —
    parses `^### V<n>` headings out of
    `docs/openfoam_corpus/industrial_solver_findings_v_series.md` and
    returns the canonical ID set. lru_cached by absolute path string so
    production hits the cache while test fixtures parse fresh.
  - `check_finding_drift(finding, index=None, *, corpus_path=None) ->
    (ok: bool, missing: list[str])` — set-difference between
    `finding.evidence_v_rows` and the loaded index. Findings citing
    zero V-rows are treated as `ok=True` (advisor explicitly waived
    TrustGate).
  - `enforce_at_route_boundary(report: AdvisorStackReport, mode:
    Literal["audit","strict"] = "audit", *, corpus_path=None) ->
    AdvisorStackReport` — returns a `dataclasses.replace`'d report
    with one appended `AdvisorCall` (`advisor_name=
    "v_series_drift_guard"`). In `strict` mode, drift Findings are
    filtered out of the new tuple; in `audit` mode (default) the
    tuple is preserved.
- Patch to `ui/backend/routes/ai_review.py`:
  - New import + step 2.5 in `post_ai_review` calling
    `enforce_at_route_boundary(report, mode=drift_mode)` after
    `assemble_stack` returns
  - `drift_mode` resolution: query param `?drift_mode=` wins over
    request body `drift_mode` field wins over default `"audit"`
  - Invalid value → 400 with `{failing_check: drift_mode_value, ...}`
- New test file `ui/backend/tests/test_v_series_drift_guard.py` (8
  tests, all green):
  1. live corpus parse → ≥100 V-rows incl. V1, V100
  2. all-hit → ok=True, missing=[]
  3. partial-miss → ok=False, missing=[bogus]
  4. full-miss + numeric sort → ok=False, missing in ascending int order
  5. audit mode → keeps findings, appends guard entry with
     `check_status="drift_detected"`, `findings_dropped=0`
  6. strict mode → drops drift findings, keeps clean + no-evidence,
     `findings_dropped` matches dropped count
  7. route integration with stubbed `assemble_stack` → guard entry
     present in `advisor_calls`; `?drift_mode=strict` drops the finding
  8. 4Q gate static AST check — module imports zero LLM provider
     modules; module body contains no `.write_text` / `.write_bytes` /
     `.mkdir` / `.makedirs` / `.rmtree` / `.copy` / `.move`

**preserved unchanged**. The two hooks are complementary, not

| axis | v1 (V61-198) | v2 (this sub-DEC) |

## drift_mode default decision

Default `"audit"`, not `"strict"`. Three reasons:

1. **Backward compatibility** — 50 existing route tests assert specific
   `findings` lengths/contents. Defaulting to `strict` would silently
   drop test fixtures' Findings if any cited an out-of-corpus literal,
   and we want the v2 invariant to be **observable**, not **invasive**,
   on its first land.
2. **First-fail observability** — operators discovering drift via the
   `audit_trail.drift_check` entry can ratchet to `strict` when they
   want enforcement (one-line opt-in via query param), rather than
   discovering it via dropped findings in production.
3. **v2.3 governance alignment** — DEC scope discipline says new
   invariants should land with the **smallest** contract delta that
   makes them observable. Audit-as-default = one new `advisor_calls`
   entry; no `findings`/`evidence_refs` deltas in any existing test.
