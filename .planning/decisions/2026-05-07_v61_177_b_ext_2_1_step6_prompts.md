# DEC-V61-177 · B-Ext-2.1 Step 6 prompts

## Motivation

R4.5 close (DEC-V61-175) showed Step-5 reach jumped from 0/3 to 2/3
but verdict pass stayed at 0/3. Trajectory analysis: backward_step
got `solve POST 200` then re-POSTed /solve and /setup-bc until
max_steps; never moved to results-summary or submit_verdict.

Root cause is **NOT async polling** (the close summary's F8 framing
was misleading): `POST /api/import/{case_id}/solve` is in fact
**synchronous-blocking** — it runs icoFoam (~30-90s wall-time) and
returns 200 only when the run has finished, with `SolveSummary`
inline (`converged`, residuals, `n_time_steps_written`,
`wall_time_s`). There is no job ID and no polling.

The bug is that personas misinterpret 200 as "submitted, run still
going" → keep POSTing /solve and /setup-bc → exhaust max_steps
without ever reading SolveSummary or moving to verdict.

## Scope

Add a dedicated **"Step 6 — post-processing & verdict"** section to
all three persona prompts that:

1. Asserts `POST /solve` is BLOCKING; 200 = run finished
2. Lists the `SolveSummary` fields that arrive in the 200 body
3. Forbids re-POSTing /solve or /setup-bc after a 200 (without a
   parameter change)
4. Defines the convergence-acceptance decision tree (converged=true
   → results fetch; converged=false + descending → bump n_iter;
   stalled/diverging → ai-diagnose → ONE conservative change)
5. Lists read-only post-processing routes in priority order
   (results-summary → run-history → residual-history.png →
   results/{run_id}/field/{name} → field-artifacts manifest)
6. Specifies verdict submission protocol (numeric scalar in same
   units as `brief.reference.value`; rationale must show arithmetic
   chain)

Voice tailoring per persona (terse for fluent, methodical for debug,
explanatory + uncertain for novice) preserved.

Plus minor unification: novice / experienced_fluent / debug all now
list `http_put` in the hard-rule allowlist (was inconsistent post
B-ext.2 — F7 fix added the tool but only updated some prompts).
