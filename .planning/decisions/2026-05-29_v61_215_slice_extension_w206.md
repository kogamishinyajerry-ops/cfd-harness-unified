# DEC-V61-215 · RunArtifactSlice extension for regionally-aware v9 advisor patterns

## TL;DR

Widen `RunArtifactSlice` (Python + TypeScript cross-language parity) with **three
optional structured post-run fields** — `developed_region_gold_delta`,
`integrated_drag_pct`, `reference_comparison_band_summary` — so that a future
W2.1 rule can distill the **DEC-V61-209 NASA-convention reference-comparison
payload** into a v9 advisor predicate. **Data-shape only**; no new rules in
this DEC. Every new field traces verbatim to existing
`trust_report.json:gates.reference_comparison.details.*` keys produced by the
unmodified DEC-V61-209 gate; no fabrication, no LLM inference, no aggregation
beyond a single `max()` over an existing list.

## Context

P1's flat-plate V&V arc (DEC-V61-209) introduced the **NASA-convention
reference-comparison gate** with four distinct pieces of evidence per case:
(i) scalar `gold_delta.max_abs_pct` (pointwise — already in slice as
`gold_delta`), (ii) regional `developed_region` max-rel-error +
n_failures/n_points/x-floor (ADDENDUM 5 #2), (iii) NASA-convention
`integrated_drag.rel_error` + verification-station Cf rel-error (ADDENDUM 4),
and (iv) near-LE `known_deviations` band (ADDENDUM 5 #2 informational pattern).

The P2 W2 plan (`.planning/strategic/p2_plan_2026-05-27.md` W2 table + meta-
finding) and the P1-close blindspot retro (`.planning/retrospectives/
2026-05-28_p1_close_p2_blindspot_findings.md` finding 5 — scalar-rule space
saturating) jointly concluded that the **DEC-209 post-run lessons cannot be
cleanly distilled into v9 rules with the current `RunArtifactSlice`**: it
carries only the scalar `gold_delta.max_abs_pct`, not the regional structure.
A rule keyed on "scalar max delta high but regionally clean + integrated metric
passes" → informational known-deviation pattern, vs. "delta high everywhere"
→ real solver bug → warn — **requires regional fields to even express the
discriminator**. Without W2.0.6, W2.1 would either invent fields at rule-
authoring time (truth-chain violation) or be cancelled.

W2.0 (per-predicate unit tests for R1–R9, commit `afeeb4a`) and W2.0.5
(truth-chain invariant tests on the ruleset) landed first as defensive
infrastructure. W2.0.6 is the **last data-contract widening** before W2.1
can responsibly distill new rules from real DEC-209 evidence.

## Decision

Extend `RunArtifactSlice` (Python dataclass at
`ui/backend/services/v9_advisor/pattern_matcher.py` + TS interface at
`ui/frontend/src/data/v9_advisor_rules.ts`) with **three optional nested-
dataclass fields**, each populated **verbatim** from existing
`trust_report.json` keys by the deriver
`ui/backend/services/v9_advisor/manifest_adapter.py::derive_slice_from_manifest`
when (and only when)
`trust_report.gates.reference_comparison.details.gate_mode == 'nasa_integrated'`.
Per-point and pre-NASA-convention legacy cases produce all three as `None`
(honest scope-out).

### New fields (v0.1 · this DEC)

| Field | Python type | Source keys (verbatim) | Purpose |
|---|---|---|---|
| `developed_region_gold_delta` | `Optional[DevelopedRegionGoldDelta]` | `details.developed_region.{max_rel_error, n_failures, n_points, developed_region_min_m}` | Regional analog to scalar `gold_delta.max_abs_pct` — distinguishes near-LE noise (out of scope for canonical Cf comparison) from developed-region shape failures |
| `integrated_drag_pct` | `Optional[IntegratedDragPct]` | `details.integrated_drag.{rel_error, within_tolerance}` + `details.verification_station.rel_error` (paired by NASA-convention) | Global integrated-Cf drag % + paired pointwise sanity-check station % |
| `reference_comparison_band_summary` | `Optional[ReferenceBandSummary]` | `details.{n_known_deviations, known_deviations[].rel_error}` + `details.developed_region.developed_region_min_m` (x-floor context) | Near-LE band rollup so future W2.1 can distinguish "global delta high but only near-LE" (informational) from "delta high everywhere" (real bug) |

### Nested dataclass schemas

- `DevelopedRegionGoldDelta(max_abs_pct: float, n_failures: int, n_points: int, min_x_m: float)`
  — `max_abs_pct = developed_region.max_rel_error * 100` (fractional → pct);
  `within_tolerance` is derivable from `n_failures == 0` so omitted to keep
  schema minimal.
- `IntegratedDragPct(pct: float, within_tolerance: bool, station_pct: Optional[float])`
  — `pct = integrated_drag.rel_error * 100`; `station_pct` paired by NASA-
  convention (both required for ADDENDUM 4 gate verdict).
- `ReferenceBandSummary(n_near_le_deviations: int, worst_near_le_pct: Optional[float], x_floor_m: float)`
  — `worst_near_le_pct` is **computed by the deriver** via a single `max()`
  over `known_deviations[].rel_error * 100` (no precomputed "worst" exists in
  source; rel_error is fractional per `flat_plate_cf.py:328` row schema);
  `None` when `n_known_deviations == 0`.

All three are `Optional` with default `None` so per-point gate-mode + empty
fixtures still construct, and the ~100+ legacy `RunArtifactSlice(...)` call
sites (predicates, behavioral eval, audit sidecar tests, frontend adapters
`useV4AdvisorMatches.ts` / `WorkbenchShellV3.tsx`) keep working unchanged.

### Deriver behavior (manifest_adapter.py)

Pure dict-in / dataclass-out. Branch on
`details.gate_mode == 'nasa_integrated'` (per
`ui/backend/audit/cfdtrust/audit/qoi.py:288` default of `'per_point'`).
Defensive `isinstance` + `try/except float` guards: a malformed
sub-dict returns `None` for that field, **not** a crash (V90 RS#34

(`x_floor_m` fallback to manifest case_manifest reference_comparison
developed_region_min_m only works when the caller has injected that key into
the manifest dict).

## Truth-chain (every new field → source line)

All three new fields trace verbatim to keys produced by
`ui/backend/audit/cfdtrust/qoi/flat_plate_cf.py::evaluate_nasa_convention`
(lines 422-444). No invented values; no LLM inference; one `max()` over an
existing list as the only aggregation:

1. `developed_region_gold_delta.max_abs_pct` ← `gates.reference_comparison.details.developed_region.max_rel_error × 100` (fractional → pct). `flat_plate_cf.py:398,407`: `dev_max = max((r['rel_error'] for r in developed_rows), default=0.0); developed_detail = {..., 'max_rel_error': dev_max, ...}`.
2. `developed_region_gold_delta.{n_failures, n_points, min_x_m}` ← `details.developed_region.{n_failures, n_points, developed_region_min_m}`. `flat_plate_cf.py:404-411`: direct keys.
3. `integrated_drag_pct.pct` ← `details.integrated_drag.rel_error × 100`. `flat_plate_cf.py:424-432`: `drag_rel = (i_run - i_ref) / i_ref; details['integrated_drag'] = {'rel_error': drag_rel, ...}`.
4. `integrated_drag_pct.within_tolerance` ← `details.integrated_drag.within_tolerance` (bool, direct).
5. `integrated_drag_pct.station_pct` ← `details.verification_station.rel_error × 100`. `flat_plate_cf.py:433-439`: `station_rel = abs((cf_run_st - cf_ref_st) / cf_ref_st); details['verification_station'] = {'rel_error': station_rel, ...}`. Paired with `integrated_drag` because the NASA-convention gate produces them together (both required for ADDENDUM 4 gate verdict).
6. `reference_comparison_band_summary.n_near_le_deviations` ← `details.n_known_deviations` (int, direct). `flat_plate_cf.py:441`.
7. `reference_comparison_band_summary.worst_near_le_pct` ← `max(r['rel_error'] for r in details.known_deviations) × 100`. **Computed by deriver** (single `max()` over existing list — no precomputed "worst" field exists in source; rel_error is fractional per `flat_plate_cf.py:328` row schema). `None` when `n_known_deviations == 0` (honest scope: no deviations means no worst). `known_deviations` is itself scoped to `x < developed_region_min_m` by `flat_plate_cf.py:395` — i.e. genuinely near-LE per DEC-V61-209 ADDENDUM 5 #2.
8. `reference_comparison_band_summary.x_floor_m` ← `details.developed_region.developed_region_min_m` (the canonical boundary used to scope near-LE). Provenance/diagnostics field — lets a future W2.1 rule predicate or audit reader know which threshold was used.

**Gate-mode discriminator** (`details.gate_mode`): when absent OR equal to
`'per_point'` (default per `ui/backend/audit/cfdtrust/audit/qoi.py:288`
`gate_mode = str(ref_block.get('gate_mode', 'per_point'))`), all three new
fields stay `None`. Per-point cases legitimately have no regional payload —
refusing to invent one **is** the truth-chain discipline.

**Source of `trust_report.json` read**: deriver caller (audit-package builder
or a real-run reader) supplies the manifest dict with `'trust_report'` key
already loaded (`json.load` happened upstream). The committed
`trust_report.json` at
`ui/backend/audit/cases/flat_plate_rans_sst/artifacts/` is the **MOCKED**
placeholder (`overall_status='MOCKED'`, no NASA fields) — deriver gracefully
returns `None` for the three regional fields against it (correct per Law-1:
don't fabricate from a placeholder). Real NASA payload reproduces via
`cfdtrust run` per `case_manifest.yaml:172-191` documented CHECKED-IN STATE
note.

## Downstream unlocks (deliberately NOT in this DEC)

Once this slice extension lands, W2.1 can responsibly distill new rules from
real DEC-V61-209 evidence without re-litigating the data contract. Specific
rule classes the extended slice enables (each a separate sub-DEC, none
shipped here):

1. **R10 known-deviation pattern** (DEC-V61-209 ADDENDUM 5 #2): "scalar
   delta > 5% but `developed_region_gold_delta.n_failures == 0` AND
   `integrated_drag_pct.within_tolerance` AND
   `reference_comparison_band_summary.n_near_le_deviations > 0`" →
   informational severity (not warning) — the **honest** outcome when global
   Cf is poisoned by near-LE noise the canonical comparison was never meant
   to score.
2. **R11 real-solver-bug regional shape** (inverse of R10): "scalar delta
   > 5% AND `developed_region_gold_delta.n_failures > 0` AND
   `integrated_drag_pct.within_tolerance == False`" → warn severity — the
   global delta reflects a developed-region failure, not a known formulation
   discrepancy.
3. **R12 station-vs-integrated discrepancy** (DEC-V61-209 ADDENDUM 4):
   "`integrated_drag_pct.within_tolerance` differs from
   `integrated_drag_pct.station_pct < 5%`" → advisory: the two NASA-canonical
   metrics disagree, which itself is a citable finding pattern.

None of these are written in W2.0.6 (`test_fixture_covers_all_rules` stays
green precisely because no new rule id appears). W2.1 owns the rule
distillation under its own sub-DEC, with provenance citations rooted in
DEC-V61-209's text + the V-series corpus.

### Cadence Codex R1 scope-outs (2026-05-30 · CRS APPROVE_WITH_COMMENTS · 2 P2 closed)

The CRS cadence review of the staged W2.0.6 diff surfaced two real gestalt
findings; both are addressed before push, and both motivate explicit follow-on
scope-outs:

- **NOT wiring `src/audit_package/manifest.py::build_manifest()` to inject a
  top-level `trust_report` key (production-side path)** — Codex R1 P2 #1
  observed that the production audit-package builder does not currently
  populate manifest["trust_report"], so the `gate_mode == 'nasa_integrated'`
  branch of `derive_slice_from_manifest()` is exercised end-to-end **only by
  synthetic test fixtures**. On real audit-package builds the three new
  slice fields stay None and the slice gracefully degrades to the pre-W2.0.6
  shape. **This is deliberate, not a defect**: W2.0.6 lands the data contract
  first; W2.0.7 (its own sub-DEC, NOT in W2.0.6 scope) will wire
  `build_manifest()` to read `<case_dir>/artifacts/trust_report.json` and
  inject the trust_report subset the deriver expects (absent → manifest has
  no trust_report key; deriver leaves new fields None — graceful-degrade-by-
  design). Scope-driven sub-DEC separation per CLAUDE.md v2.3 ("sub-DEC scope
  driven; data-contract first, production wiring second, rule distillation
  third"). **DO NOT add yaml/json file IO to manifest_adapter.py** to "close
  the gap" — RS#35 allowlist forbids and any IO belongs in the builder, not
  the pure deriver.
- **NOT fabricating `x_floor_m = 0.0` when developed_region_min_m is absent**
  (Codex R1 P2 #2) — `ReferenceBandSummary.x_floor_m` is now `Optional[float]`
  (Python) / `x_floor_m?: number` (TS). When both source paths
  (`details.developed_region.developed_region_min_m` AND the
  `case_manifest.reference_comparison.developed_region_min_m` fallback) yield
  no value, x_floor_m stays None. Substituting 0.0 would silently relabel
  "cutoff unknown" as "cutoff at the leading edge" — a truth-chain violation
  that would mislead any future near-LE rule/UI consumer. The band summary
