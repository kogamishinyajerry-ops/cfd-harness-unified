# DEC-V61-217 · P3 CHT charter — wire chtMultiRegionSimpleFoam end-to-end + region-aware extractor extension + CHT V&V loop (laminar pure-CHT v0.1)

## TL;DR

P1 (RANS-aero V&V loop) and P2 (pre-flight signals + v9 R10/R11/R12 substantive
distillation) are both **structurally closed** — DEC-V61-211..216 all Accepted +
Notion-synced; v9 ruleset reached 12 rules; phase-close retro `2026-05-30_p2_phase_close.md`
landed. Under **Blueprint v4 Law 1 (runnable-coverage)**, the next unlock is the
**second runnable-covered compute type**: CHT (conjugate heat transfer). CHT is
*currently declared-only by absence* — the generation-side path is empty:
`src/foam_agent_adapter.py:732-789` enumerates dispatch branches for
BACKWARD_FACING_STEP / NATURAL_CONVECTION_CAVITY / BODY_IN_CHANNEL / AIRFOIL /
IMPINGING_JET / SIMPLE_GRID with zero `chtMulti*` route (verified by
`grep -i chtMulti` returning zero hits in the adapter); the audit-side multi-region
BC parser was already hardened by **DEC-V61-201-SUB** but the workbench cannot
*generate* a CHT case at all, so the audit path has never been exercised end-to-end
on a workbench-authored CHT case.

P3 makes CHT the **second runnable-covered compute type** under Blueprint v4 §6
by following the exact W2.0.6 → W2.1 sequencing pattern P2 proved (slice contract
BEFORE rule distillation, per P1-close blindspot finding 5 — scalar saturation —
and P2 W2 meta-finding). The vertical-first sequence within P3: **textbook canonical
benchmark FIRST** (Patankar §6 / Bejan compact-HX / Kays-Crawford family — tabulated
+ citable, mirrors NASA TMR's role for P1), industrial dogfood (case_011 plate-fin
compact HX) **AFTER** the V&V loop closes. Scope clamps to **pure CHT v0.1**
(conduction + convection · laminar · steady-state · single-phase · non-radiating
· non-porous · non-phase-changing) per Consideration 4's "pre-state scope-outs
to avoid mid-implementation overrides" lesson from DEC-V61-214. Each scope-out
is reversible via a future sub-DEC if the user overrides.

## Context — North Star + the three Blueprint v4 laws applied to P3

CHT today (per `strategic/blueprint_v4_2026-05-27.md` §6, the runnable-coverage
map): ❌ NOT runnable. Knowledge present (`case_002b_apu_bay_cht.md` reference
profile + `case_011_plate_fin_compact_hx.md` industrial dogfood profile + V-series
death-chains V14/V15/V63-A/V85/V90/V92/V93/V94 + case_028 V65 deferral all
sediment from the DEC-V61-198 arc), audit-side BC parser hardened
(DEC-V61-201-SUB LANDED), generation-side missing.

Under the Blueprint v4 three laws:

- **Law 1 · Runnable-coverage** (`blueprint_v4_2026-05-27.md` §3): a compute type
  is "covered" only when its solver runs end-to-end **AND** a benchmark passes
  its tolerance gate. The P3 exit gate is the canonical instantiation of Law 1
  for CHT: runnable-coverage transitions **1 → 2** when the textbook canonical
  benchmark passes its tolerance gate through the workbench end-to-end. Profiles
  and death-chains are knowledge, not coverage.
- **Law 2 · V&V loop as a first-class flow**: `run → compare-to-gold → quantified
  error → TrustGate verdict`. W3.3 instantiates Law 2 for CHT by mirroring the
  DEC-V61-209 triad (integrated metric + station + per-point developed-region)
  with a CHT-canonical version (integrated HTC + station Nusselt + per-point
  wall-T past entry-length floor). Either-metric-alone-gameability is the design
  constraint that gates benchmark-family selection.
- **Law 3 · AI distillation path**: the Claude session distills V-series CHT
  death-chains into the offline v9 ruleset; the ruleset ships and runs without
  AI. W3.1 distills 3–4 CHT rules (R13..R16 candidate range) consuming the
  W3.0.6 multi-region slice extension. Each rule offline-runnable, each cites
  ≥1 V-row it would have caught (canonical DEC-V61-216 carry-forward).

## Decision

1. **CHT as the P3 second runnable-covered vertical · pure CHT v0.1** —
   conduction + convection, laminar, steady-state, single-phase, non-radiating,
   non-porous, non-phase-changing. Solver: `chtMultiRegionSimpleFoam` (steady-state
   variant; transient `chtMultiRegionFoam` deferred). This is the minimal
   honest CHT envelope that exercises multi-region topology + thermo coupling
   + interface BCs without dragging in turbulence-model or radiation-model
   complexity that would re-saturate the scalar-rule space (per P1-close
   blindspot finding 5).

2. **W3.0.6 multi-region RunArtifactSlice extension MUST precede W3.1 CHT rule
   distillation.** P1-close blindspot finding 5 ("scalar rule space saturating")
   predicted this; P2 W2.0.6 → W2.1 sequencing confirmed it; P3 plans around it.
   Attempting to write CHT rules against the current scalar slice would
   manufacture theater rules with no discriminating power — CHT death-modes are
   *spatial/regional* (per-region thermo gaps, interface coupling mismatches,
   per-region face-zone loss) and cannot be squeezed out of a scalar saturated
   space. Concrete sequencing: W3.0 (regionProperties reader) → W3.0.1 + W3.0.2
   + W3.0.3 (per-region extractor variants) → W3.0.6 (multi-region slice
   extension) → W3.1 (CHT rule distillation) **gated** on W3.0.6 landing.

3. **Benchmark FAMILY = textbook canonical (Patankar §6 / Bejan compact-HX /
   Kays-Crawford) gated FIRST; case_011 plate-fin industrial dogfood AFTER V&V
   loop closes.** Same architecture as P1: NASA TMR flat-plate (V&V) → APU-bay
   (industrial dogfood). Rationale: textbook canonical references are tabulated
   and citable in machine-readable form, mirroring the DEC-V61-209 W1.0
   gold-standard `canonical_conditions` pattern; case_011 v5b previously hit V94
   face-zone loss + V93 degenerate-physics conduction-dominated
   boundary-equilibration (per DEC-V61-198 sediment), which is precisely the
   load-bearing precedent for the "textbook FIRST · industrial AFTER" default
   — running industrial first would let dogfood failure modes contaminate the
   V&V gate selection. Exact tolerance + canonical-conditions data file are
   deferred to a future sub-DEC `DEC-V61-Y CHT benchmark V&V` (mirrors
   DEC-V61-209 sequencing where flat-plate V&V was a separate sub-DEC inside
   the P1 arc, not the P1 charter).

4. **Gate-mode SHAPE mirrors DEC-V61-209 triad** — (i) integrated HTC over the
   wall/fluid-solid interface, (ii) station Nusselt number at a canonical
   streamwise verification station, (iii) per-point wall-temperature T_wall(x)
   past the entry-length developed-region floor. Pass iff
   `integrated_ok AND station_ok AND developed_ok` (per DEC-V61-209 ADDENDUM 5
   pattern — either-metric-alone is gameable). XOR disagreement between
   `integrated_ok` and `station_ok` is the CHT analogue of R12 (W3.1 R16
   candidate). Entry-region thermal-boundary-layer developing band is
   *demotable to* `known_deviations` (visible, not hidden — DEC-V61-209
   ADDENDUM 5 #2 carry-forward). Exact tolerance numerals + canonical
   verification-station x_m + canonical-conditions data file are deferred to
   `DEC-V61-Y` per Consideration 3 recommendation; charter pins only the
   shape so the gate is non-gameable by design.
