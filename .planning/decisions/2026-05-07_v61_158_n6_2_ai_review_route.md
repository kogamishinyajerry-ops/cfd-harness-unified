# DEC-V61-158 · N6.2 · AI 审查 Advisor Route

## Scope

Read-only `GET /api/cases/{case_id}/ai-review` route returning a
citation-grounded `ReviewResponse`. LLM path uses N6.1 corpus +
existing LLM provider abstraction; offline path uses N5.2 honest
issue list + corpus keyword grounding. Findings without resolvable
citation are dropped (charter §"Why citation grounding is mandatory").

## Surface delivered

- `ui/backend/schemas/ai_advisor.py` — `ReviewFinding`, `ReviewResponse`,
  `FindingArea`, `FindingSeverity`, `FindingSource` (extended)
- `ui/backend/services/ai_advisor/review.py` — `review_case`, prompt
  builder, LLM JSON parser with chunk-id grounding, rule-based
  fallback wired to `enumerate_issues` (N5.2)
- `ui/backend/routes/ai_advisor.py` — GET endpoint with case-id
  validation (`is_safe_case_id` + `IMPORTED_DIR / case_id` check)
- `ui/backend/main.py` — router registered at `/api`
- `ui/backend/tests/test_ai_advisor_contract.py` — `_AI_DISPATCH_MODULES`
  extended with 4 N6 module paths (route + service init + corpus
  loader + review service); Layer-C AST scan auto-covers them
- `ui/backend/tests/test_n6_2_ai_review.py` — 16 tests covering
  schema + offline path + LLM path (valid / hallucinated chunk_id /
  malformed JSON / provider raises) + route (200/400/404) + V132
  Layer-A sentinel patches across both branches

## Notes

- LLM prompt locks the citation contract: "cite only chunk_ids from
  CORPUS block; drop any finding you cannot ground"
- Service does not import `KNOWN_MUTATION_FUNCTIONS` symbols (Layer-C
  static check), and route exercise across both branches does not
  invoke any (Layer-A sentinel)
- IssueScope (5 values) → FindingArea (5 values) cast is identity;
  explicit map kept as future-proofing
- `recommended_change` is a metadata-only string; never a callable
  or route descriptor; UI renders as text + copy button (N6.4)
- N6.5 will broaden the rule-based fallback set (currently only
  `enumerate_issues` outputs are converted; URF/timing/checkMesh
  advisor outputs to be added)
