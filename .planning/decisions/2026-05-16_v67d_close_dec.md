## 4 · Implementation summary

### `build_canonical_manifest.py`

- Walks `.planning/evals/canonical/` and `.planning/evals/runs/` for `.md` files
- Computes SHA-256 hash per file
- Writes `MANIFEST.sha256` with `<sha>  <relpath>` format (one line per file)
- Default mode = verify; `--update` mode = rebuild
- Exit codes: 0=ok · 1=drift · 2=missing · 3=orphan

### `verify_eval_set_integrity.py`

4 structural checks:
1. INDEX.md references all 20 case IDs (E01-E20)
2. Each case ID has either a detail file OR a batched file section
3. Every advisor rule cited in eval files resolves to either:
   - V66-B new rules in `advisor_rules_v66b_expansion.md`
   - V64-A baseline rules listed in SDK doc
   - Explicitly-registered V13x candidates (7 known: rhoCentralFoam, substrate_inspection, yplus_target_validation, residual_gate_qualifier, transition_onset_validator, shock_capturing_scheme, multi_element_high_lift)
4. Every E** reference in run logs maps to a valid case ID

Exit codes: 0=ok · 1=case doc missing · 2=orphan advisor rule · 3=invalid run log ref

### `.github/workflows/eval-set-integrity.yml`

Triggers on push/PR to:
- `.planning/evals/**`
- `.planning/methodology/advisor_rules*`
- `.planning/sdk/**`
- `scripts/eval/**`
- workflow file itself

Runs both scripts. Independent of existing `ci.yml` (separate workflow, separate job).
