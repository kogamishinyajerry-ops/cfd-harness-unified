## V130 BY-CONSTRUCTION discipline

V90's defining design property: **V130 honored by construction, not by
gating.** Five lines of defense from V83-V89 stay intact AND V90 adds a
sixth class of evidence (literal-source absence):

1. **Lexical denylist** (V83.1 · V90.4 contract test asserts "AI generates / AI
   suggests / AI diagnoses / AI recommends / AI advises" all absent from
   rendered text)
2. **Structural fetch-zero at mount** (V83.2 · V90.4 contract test asserts
   regex `\buseEffect\b`, `\bfetch\(`, `\buseQuery\b` all absent from
   PostRunAdvisorV9.tsx code after stripping JSDoc + line comments)
3. **Architectural V132=9 mutating-routes lock** (V84 · unchanged by V90 ·
   no new mutating route added)
4. **Live browser confirmation** (V85+ · sandwich-test pattern still
   applies, V90 e2e specs cover it for V9)
5. **Env-gated visualization-only injection** (V89.2 · isolation between
   dev/test inspection affordances and prod behavior preserved)
6. **NEW: Literal-source LLM-endpoint absence** (V90.4 contract test reads
   the actual `.tsx` source file, strips comments, asserts NO `/ai-review`,
   `/ai-diagnose`, `streamAICoach`, `ai_advisor`, `from "@/api/client"`
   imports survive in code — comments referencing these strings to explain
   what's banned are OK; actual imports are not. This is a stronger
   guarantee than mount-time inspection — it asserts the surface CAN'T do
   it, not just that it WON'T)

The V9 component is therefore an **architectural impossibility for LLM
runtime call**, not just a runtime-disciplined one.

## V9.D forward-plan (NOT in V90 scope)

V9.D — "commentary sidecar inside audit_package.zip" — is documented in
the V9 blueprint as a V91+ deliverable, NOT a V90 deliverable. Rationale:

- V90 already delivers 5 of the 11 reverse-stops on the V9 contract; sub-DEC
  density was sufficient for a single LAND
- Sidecar emission requires touching the audit-package emitter (backend +
  scripts/audit) which is on a different change cadence than the frontend
  advisor surface
- Pattern matcher + ruleset are pure-data + pure-function; same matcher
  invoked from a Node-side sidecar emitter will produce **byte-identical**
  matched-commentary entries, so V90's evidence carries forward to V9.D
  without rework
- V9.D scope: extend `audit_package.zip` schema with a top-level
  `commentary/matched.json` array of `MatchedCommentary` objects, replay
  matcher against the same RunArtifactSlice that audit_package consumes,
  bytewise-deterministic across re-emission

V91+ should land V9.D as a single sub-DEC; will not need a new arc charter.
