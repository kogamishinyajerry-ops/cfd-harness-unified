# DEC-V61-192 · B-ext-5.1 · F14 mitigation

## Status

**Accepted 2026-05-07** — first sub-DEC under B-ext-5 charter
(V61-191). Tightens the persona-side LLM-client timeout/retry
behavior that R9 surfaced as F14.

## Root cause

R9 backward_step crashed at step 20 with `llm_chat_failed: The read
operation timed out` after waiting **15.5 minutes** (1778151942 →
1778152876 = 934s) on a DeepSeek chat-completions response.

`OpenAICompatClient` was constructed with `timeout=60.0`, which httpx
expanded to `Timeout(connect=60, read=60, write=60, pool=60)`. The
read-timeout deadline measures **between bytes**, not total request
time — so a slow trickle of TCP keepalives (or partial header bytes
under upstream pressure) extends the wait without ever triggering the
60s deadline.

This is NOT a workbench-side issue. DeepSeek API upstream instability
under our R8/R9 sustained-load pattern is the immediate cause; the
client lacked any retry safety net to recover.

## Fix

`scripts/dogfood/llm_clients.py`:

1. **Module-level constants** for default timeout + retryable
   exceptions:

   ```python
   _DEFAULT_TIMEOUT = httpx.Timeout(
       connect=10.0, read=180.0, write=30.0, pool=30.0
   )
   _RETRYABLE_EXC = (
       httpx.ReadTimeout, httpx.WriteTimeout, httpx.ConnectTimeout,
       httpx.PoolTimeout, httpx.RemoteProtocolError, httpx.ConnectError,
   )
   ```

2. **`_resolve_timeout(timeout)`** helper accepts legacy `float`
   callers and coerces to per-phase `Timeout` (read=value,
   connect/write/pool capped to 10/30/30).

3. **`_post_with_retry(client, url, *, json, headers, retries=1,
   backoff_s=5.0)`** wraps `client.post()` with up to 1 retry on
   `_RETRYABLE_EXC`. HTTP 4xx/5xx pass through untouched (caller
   handles via `raise_for_status`).

4. Both `OpenAICompatClient.chat()` and `AnthropicClient.chat()`
   replace direct `client.post(...)` with `_post_with_retry(...)`.
   Constructor `timeout: float = 60.0` becomes
   `timeout: float | httpx.Timeout | None = None`.

Worst-case wait under failure now: 60s (read) + 5s (backoff) + 180s
(retry read) = **~4 minutes** before persona_runner sees the failure
(vs 15.5 min in R9). Best-case under transient failure: clean recovery
with `attempts=2` and ~5s extra wall-time.

## Tests

`tests/dogfood/test_llm_clients.py` adds 5 new tests:

- `test_default_timeout_is_per_phase_with_read_180s` — schema contract
- `test_resolve_timeout_accepts_legacy_float` — back-compat for legacy
  float callers
- `test_post_with_retry_succeeds_after_one_read_timeout` — first
  attempt raises `ReadTimeout`, second returns 200; mirrors the R9
  failure mode
- `test_post_with_retry_reraises_after_exhausted_retries` — two
  consecutive `ReadTimeout`s re-raise to caller (so persona_runner
  still sees the failure once retries are spent)
- `test_post_with_retry_does_not_retry_on_4xx` — HTTP 401/4xx is NOT a
  network error and must not be retried (caller's
  `raise_for_status` surfaces it)
- `test_anthropic_client_also_retries_on_read_timeout` — same code
  path for AnthropicClient (uses `RemoteProtocolError` to vary the
  exception type)

29/29 tests pass (24 existing + 5 new).
