# DEC-V61-193 · B-ext-5.2 · F13 mitigation

## Status

**Accepted 2026-05-07** — second sub-DEC under B-ext-5 charter
(V61-191). Adds a workbench-side pre-flight check to catch the most
visible mode of F13 (`/solve` 502 Bad Gateway) and route it to a
structured 409 with `failing_check=mesh_missing` instead.

## Root cause investigation

Manual repro on a fresh naca0012 case staged via `/api/import/stl` →
`/setup-bc?from_stl_patches=1` (NO `/mesh` call) → `/solve`:

```
{"detail":{"failing_check":"solver_diverged",
 "detail":"simpleFoam exited with code 1; see ...log.icoFoam"}}
HTTP_STATUS:502
```

The `log.icoFoam` shows:
```
--> FOAM FATAL ERROR:
Cannot find file "points" in directory "polyMesh" in times "0" down
to constant
```

Inspection of the host case dir confirms `constant/polyMesh/` is
absent entirely. R9's 11× `/solve` 502 events were almost certainly
this mode — the persona reached an inconsistent state where polyMesh
files were missing or incomplete, hit `/solve`, and got back a generic
502 with a cryptic OpenFOAM IO error string buried in the detail field.

## Why the existing pre-flight didn't catch it

B-ext-3 F10 added `_check_mesh_bc_consistency()` to catch
mesh-after-setup-bc patch-name mismatches. Its docstring explicitly
says it returns `None` when polyMesh is absent — that case was
delegated to "solver_runner's existing controlDict check or the
caller's case-shape validation", but **no such check existed for the
polyMesh case**. controlDict presence was checked; polyMesh presence
was not.

## Fix

`ui/backend/services/case_solve/solver_runner.py`:

```python
def _check_mesh_present(case_host_dir: Path) -> str | None:
    polymesh_dir = case_host_dir / "constant" / "polyMesh"
    if not polymesh_dir.is_dir():
        return f"mesh_missing: no constant/polyMesh/ directory at ..."
    boundary_file = polymesh_dir / "boundary"
    points_file = polymesh_dir / "points"
    missing = [f.name for f in (boundary_file, points_file) if not f.is_file()]
    if missing:
        return f"mesh_missing: constant/polyMesh/ exists but is incomplete (missing {missing})..."
    return None
```

Wired into `run_icofoam` BEFORE the F10 mesh-BC consistency check:

```python
mesh_missing = _check_mesh_present(case_host_dir)
if mesh_missing is not None:
    raise SolverRunError(mesh_missing)
mismatch = _check_mesh_bc_consistency(case_host_dir)
...
```

`ui/backend/routes/case_solve.py`:

- Both the blocking `/solve` route and `/solve-stream` map
  `mesh_missing:` exception prefix to **HTTP 409 +
  `failing_check=mesh_missing`** (NOT 502).
- For symmetry the streaming route also maps `mesh_bc_mismatch:` to
  409 (the blocking route already did this; the streaming route had a
  gap that this DEC fills incidentally).

## What this fix does NOT cover

This is a **partial** mitigation. R9's 11× /solve 502 had two
contributing factors:

1. **Missing polyMesh** (this DEC's fix) — most-visible mode, reproed
   directly via curl.
2. **Solver-launch race or resource pressure under sustained
   automation** — R9 left an ephemeral `compassionate_neumann`
   container running 42 min, suggesting solver-spawn isn't fully
   cleaning up between calls. This is NOT addressed here.

R7 curl direct E2E and R8 backward_step persona drive both achieved
/solve 200 on first try; the 502 mode only surfaced under R9's
sustained 31-min run. Hypothesis 2 needs reproduction under load
before a targeted fix; deferred to potential B-ext-5.3 if it surfaces
again in B-ext-5.4 / 5.5 runs.
