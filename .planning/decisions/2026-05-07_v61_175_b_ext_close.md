- **F6** (per-turn input bandwidth) — pruning fired 7-15× per run in
  R4; cumulative input similar to R3 (650k vs 670k) but per-turn

  gains require either tighter prune (R4.5: keep_full=3) or

  reached Step 4 setup-bc 200. Persona prompts directing to

  in R3). Hypothesis: persona spent more turns on patch-discovery

## Path to verdict pass

Each cell needs: import (Step 1) → mesh (Step 2) → physics (Step 3)
→ patch-split (F7 sub-step, conditional) → setup-bc (Step 4) → solve
(Step 5) → results-summary fetch → submit_verdict.

Backward_step at R4 reached Step 4 in 22 turns. Estimated remaining:
~5-8 turns for solve + post-processing. R4.5's bigger budget
(1.5M cumulative) + tighter prune (keep_full=3) targets this gap.

## New finding F8 — async solve job lifecycle blocks verdict

R4.5 is the first iteration where workbench responsiveness is no
longer the bottleneck. The new bottleneck is:

- POST `/solve` (or `/solve-stream`) returns immediately with a
  job ID; OpenFOAM runs in the background
- Persona must poll for completion (e.g., `/run-history/{run_id}`,
  `/results-summary`, `/residual-history.png`) before submitting
  verdict
- This polling phase requires ~10-20 additional turns (poll →
  read residuals → assess convergence → fetch field data →
  compute reference metric → submit_verdict)
- R4.5 max_steps=50 + 1.5M tokens are insufficient for both
  Steps 1-5 (~25-30 turns) AND post-processing (~10-20 turns)

**B-ext-2 candidate fixes** (out of scope for B-extend V1):

1. Persona prompt section "Step 6: post-processing & verdict" with
   explicit lifecycle guidance (poll until status=converged, fetch
   results-summary, compute metric, submit_verdict)
2. Bump max_steps to 80 + max_input_tokens to 3M (DeepSeek budget
   is plentiful per user; main session can afford it)
3. Workbench-side: optional `/solve-sync` mode that blocks until
   completion (kept opt-in to preserve UI streaming behavior)
4. Or: workbench-side response trimming (smaller mesh-quality and
   /actions catalogue payloads)

Realistically, (1) + (2) alone should produce verdict pass ≥ 1/3 in
R5; (3) + (4) are nice-to-have not necessary.
