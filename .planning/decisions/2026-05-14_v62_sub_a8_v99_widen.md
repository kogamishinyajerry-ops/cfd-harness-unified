# DEC-V62-A-sub-A8-V99-WIDEN · close case_011 v5b 6/8 false-positive gap

## Status

**Accepted 2026-05-14** — Tier 2 supplement that widens
`shm_dict_validator`'s Path (b)/(b')/(c) cross-reference checks to
honour the native OpenFOAM snappyHexMeshDict idiom of `.stl`-filename
geometry keys with `name:` alias attributes. Pure validator-internal
refinement: no advisor signature change, no new finding code, no V-row
addition (V99/V100 already in V-series corpus + already in
`_V_ROWS_PER_ADVISOR["shm_dict_validator"]`). confidence: med (single
file + tightly scoped behaviour change; backward-compat preserved by
keeping `ShmDictReport.geometry_names` as literal keys and falling back
to literal-key matching when no alias is present).

## Goal

Close the M-STACK-TRACK-1 §8 enhancement #1 gap verbatim:

> **§8 #1** "Patch `shm_dict_validator` to resolve `name:` alias
> before key match (~30 LOC + 2 tests; spike-class candidate per v2.3
> round-1 loosen). Single highest-leverage fix — eliminates 6
> false-positives per CHT case and unblocks honest measurement of the
> stack's true industrial signal."

The case_011 v5b dict (`scripts/stack_track_c_session_1/case_011_v5b_payload.json`)
keys geometry by source STL filename:

```json
"geometry": {
  "region_hot_fluid.stl": { "type": "triSurfaceMesh", "name": "region_hot_fluid" },
  "region_cold_fluid.stl": { "type": "triSurfaceMesh", "name": "region_cold_fluid" },
  "region_solid.stl":     { "type": "triSurfaceMesh", "name": "region_solid" }
}
```

`refinementSurfaces` then references the `name:` alias (canonical patch
token), not the `.stl` literal key. Pre-widening A8 did a literal
`surf_name not in geometry_names` check (which used `geometry.keys()` =
the `.stl` filenames), so every alias-keyed reference triggered both
`missing_geometry_ref` (Path b) and `geometry_orphan` (Path b') — 6
false-positives for a 3-region CHT case authored in correct OpenFOAM.

This single-step scope-bounded widening (a) lights up real-world CHT
inputs from the foamDictionary parser path without further plumbing,
and (b) unblocks an honest TRACK-1 re-run measurement of stack signal
without the noise pollution that suppressed the 25 % adoption rate
below the 70 % bar.

## Scope (what changed) + 反向声明 (what did NOT change)

### Changed

1. `ui/backend/services/geometry_ingest/shm_dict_validator.py`
   * Added `_strip_geometry_alias(raw: str) -> str` (V100-WIDEN
     defensive single-layer parens-stripping for foamDictionary
     wordList-output convention).
   * Added `_resolve_geometry_aliases(geometry) -> (literal_keys,
     alias_map, all_effective_names)` helper that builds the union of
     literal keys + `name:` aliases per geometry entry.
   * Path (b) `missing_geometry_ref` check now uses
     `all_effective_names` membership (alias-aware) instead of literal
     `geometry_names`.
   * Path (c) `missing_region_ref` check same alias-aware widening.
   * Path (b') `geometry_orphan` check: an entry counts as referenced
     if **any** of its effective names appears in `refed`; orphan
     finding still reports the literal key as the actionable location.
   * Module docstring updated to reference V99-WIDEN + parent sub-DEC.

2. `ui/backend/tests/test_shm_dict_validator.py` — 5 new tests below.

### Explicitly NOT changed

* No V-row additions — V99/V100 already present in
  `docs/openfoam_corpus/industrial_solver_findings_v_series.md` and
  `_V_ROWS_PER_ADVISOR["shm_dict_validator"] = ("V52", "V86", "V99",
  "V100")` in `ui/backend/services/advisor_stack.py:175`. This is a
  scope widening of existing V-rows, not new V-row coinage.
* No advisor signature change — `validate_shm_dict()` keeps its
  existing `(parsed_dict, *, available_emeshes, stl_face_normals)`
  arity.
* No `ShmDictReport.geometry_names` shape change — still a tuple of
  literal `geometry.keys()` (backward-compat for downstream consumers
  such as `advisor_stack._normalize_shm_dict_findings`).
* No Path (e) V99 constrained-patch STL face-normal check change —
  case_003 v2 sediment behaviour intact. Path (e)'s `surf_name` already
  comes from `refinementSurfaces.keys()` which is the canonical name
  (whether alias-derived or literal), and the caller is responsible
  for keying `stl_face_normals` by the same name — no aliasing needed
  inside Path (e).
* No Path (d) typo-suspicion change — fuzzy-match walker is canonical-
  vocabulary driven, unrelated to geometry-name aliasing.
* No threshold change — `_COLINEAR_DEVIATION_MAX`,
  `_LEVENSHTEIN_MAX`, `_CONSTRAINED_PATCH_TYPES` all untouched.
* No `_V_ROWS_PER_ADVISOR` mutation in `advisor_stack.py` — A8 row
  unchanged. B33 (D10 bc_type_name_validity_advisor parallel work) may
  add a new D10 row; the A8 row and any D10 row are non-conflicting
  dict entries.
