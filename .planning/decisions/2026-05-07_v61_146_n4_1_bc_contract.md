# DEC-V61-146 · N4.1 BC Contract

## Status

**Accepted 2026-05-07** — V133 sub-DEC slim 6-field. Medium-risk per
N4 charter; Opus confidence high — pure additive surface, V132
contract preserved (Layer-A patched-function sentinel + AST namespace
test green), no Codex pre-merge per "per Opus confidence" charter row.

## Decision

Land the structured per-patch BC contract end-to-end:

- 10 BC types as discriminated-union Pydantic models
  (velocity_inlet / volumetric_flow_inlet / mass_flow_inlet /
  pressure_outlet / inlet_outlet / no_slip_wall / moving_wall /
  symmetry / cyclic / empty)
- BCContract top-level schema with patch-name charset enforcement
  + cyclic pairing invariants (bidirectional + both-cyclic checks)
- Writer translating BCContract → 0.orig/U + 0.orig/p (atomic
  write via mkstemp + os.replace)
- POST /api/cases/{case_id}/bc-contract route + V132 registration

## Frontend BC palette deferred

The N4 outline §"four-question gate Q1: form-driven BC" is satisfied
by **schema validation at the contract level** in N4.1; the visual
BC palette panel that lets engineers pick BC type per patch via UI is
deferred to N4.2 (when the unified Step 3 Physics setup workbench
shell lands and consumes both BCContract and the solver dict editor).
This is consistent with the N3 pattern where N3.1 + N3.2 shipped

lands in N4.2.

## Wire shape

```python
PerPatchBC = Annotated[
    Union[
        VelocityInletBC, VolumetricFlowInletBC, MassFlowInletBC,
        PressureOutletBC, InletOutletBC,
        NoSlipWallBC, MovingWallBC,
        SymmetryBC, CyclicBC, EmptyBC,
    ],
    Field(discriminator="bc_type"),
]

class BCContract(BaseModel):  # extra=forbid
    patches: dict[str, PerPatchBC]  # at least 1 entry
    authored_at: str  # ISO 8601
```

Status mapping:
- 200 → BCContractCommitResponse
- 400 → bad case_id
- 404 → case_not_found
- 422 → contract validation error (Pydantic) OR
  `failing_check: bc_type_unknown` (writer dispatch) OR
  `failing_check: case_not_scaffolded`
- 502 → `failing_check: bc_write_failed`

## Cyclic pairing invariants (model_validator-enforced)

1. Every cyclic patch's `paired_patch` MUST exist in `patches` dict
2. The paired patch MUST also be `bc_type=cyclic`
3. Pairing MUST be bidirectional (A→B AND B→A)

Single-direction cyclic declarations or pairing with non-cyclic
patches surface as 422 with the violating-rule message — saves the
engineer a round-trip through OpenFOAM solver-startup error messages.
