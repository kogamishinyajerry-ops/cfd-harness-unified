## 5 · Honest disclosures

### What V74 did NOT do
- Did NOT integrate vtk.js (V71.L bookmark aged into V74).
- Did NOT close V71.L SSE residual integration.
- Did NOT widen backend `_resolve_case_dir` (V73.1 UI-side pre-flight still in effect).
- Did NOT verify the backend `audit-package/build` route is actually wired end-to-end — the UI wire is in place but live backend execution wasn't smoke-tested in V74 (Pillar 12 integration_tests covers the static evidence, not the round-trip).

### Substrate fragility uncovered
- TS literal-testid requirement: the Pillar 13 scorer's grep expects literal `data-testid="provenance-hash-corpus"` patterns. Initial V74.3 implementation used template literals (`data-testid={`provenance-hash-${id}`}`); the source compiled and rendered correctly but the scorer saw 0 matches. Refactored to four explicit chip components.
- Similar happened with `data-source="live"` literal vs `data-source={variable}` in TopBar.
- Lesson for V75 charter: scorer regex should accept both literal AND template forms, or convention must mandate literals (V74 took the literal-source path).

### What V74 measured for the first time
- Pillar 13's existence forces the v3 surface to expose canonical provenance — buried before V74 in completeness/validation reports, now first-class UI affordance.
