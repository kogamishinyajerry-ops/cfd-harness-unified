# DEC-V61-222 · CHT v9 advisor rule distillation (P3 W3.1)

## Context

DEC-V61-217 W3.1 — the CHT analogue of W2.1 (DEC-V61-216 R10/R11/R12): distill
3–4 offline v9 advisor rules from the V-series CHT death-chains, consuming the
`RunArtifactSlice.regions` contract frozen in W3.0.6 (DEC-V61-221). Gated on
W3.0.6 (landed). Charter candidates: R13 wall-coupling-type-mismatch / R14
per-region-thermo-missing / R15 conduction-dominance / R16 face-zone-loss.

Surface scan (V61-088): the v9 ruleset is a **4-layer contract** — JSON SSOT
(`v9_advisor_rules.json`) + Python predicates (`rules.py`) + TS predicates
(`v9_advisor_rules.ts`) + a cross-language parity contract test + parity fixtures.
Any rule lands across all four. Disposition: **extend** (additive R13/R14;
R1–R12 untouched).

## Decision

Ship **two faithful CHT rules** into the offline v9 ruleset (final = 14 rules,
v9.4.0); defer two candidates that have no faithful signal in the frozen schema.

### Shipped (each a pure offline predicate over `RunArtifactSlice.regions`; advisory `warn`)

- **R13 `COUPLED_INTERFACE_DANGLING_REF`** ← `coupled_patches[*].neighbour_region`
  vs the region-name inventory. Fires when a coupled patch names a neighbour
  region absent from the inventory — the slice-level shadow of **V94** ("Cannot
  find patchField entry for region_hot_fluid_to_domain0"). *Regrounded from the
  charter's "wall-coupling-type-mismatch"* (which red-team proved unsound — a
  case-wide Rad/non-Rad heuristic that false-fired on healthy mixed-physics cases,
  carried dead `neighbour_map` scaffolding, and would not have caught its cited V94).
- **R14 `PER_REGION_THERMO_MISSING`** ← `thermo_type` + `thermo_snapshot_ref` both
  None on a listed region. Catches **V14** (sentinel ±1e+300 from a crashed region)
  / **V92** (region dropped from polyMesh) — a region declared but with no
  per-region thermo payload (DEC-V61-213 presence-vs-payload).

### Deferred (no faithful signal in the frozen W3.0.6 schema — Codex R1)

- **R15 `CONDUCTION_DOMINANCE`** (would read `kind`) — `kind` is DECLARED topology
  from `regionProperties`; a mesh-lost fluid still reads `kind="fluid"`, so a
  zero-fluid count cannot detect the V92 mesh-loss it claims.
- **R16 `FACE_ZONE_LOSS`** (would read `shm_snapshot_ref`) — `shm_snapshot_ref=None`
  means "extruded, not sHM'd" (healthy for case_002b's 6 `extrudeToRegionMesh`
  solids), NOT "face-zone lost" → false-positive on the canonical case.

Both need a **per-region produced-mesh-presence signal** (cell-presence /
faceZone-presence) the schema lacks. The honesty constraint ("each rule names ≥1
V-row it would have caught") forbids shipping them as-is. Mirrors the V15 honest-gap
precedent (no slice signal → not productized).

### Production reachability

W3.1 ships the rules + the **deriver-path** consumer readiness:
`derive_slice_from_manifest()` now reads `manifest["regions"]` via a
bulletproof-graceful `_regions_from_manifest()` (106 adversarial cases, zero
raises; honest-refusal; three-state preserved), proven end-to-end through the REAL
`matches_for_manifest()`. This **defines the `manifest["regions"]` contract** W3.2
must emit. The UI live-card path (run-detail API emission + UI adapters) was
reverted (Codex R2) — it is one coherent W3.2 unit.
