# DEC-V61-183 · B-Ext-3.3 E2E contract test

## Status

**Accepted 2026-05-07** — 3 contract tests added to lock in F10 fix
behavior at the route boundary. Runs without Docker. 3/3 pass.

## Tests

`ui/backend/tests/test_solve_mesh_bc_contract_e2e.py`:

1. `test_solve_returns_409_mesh_bc_mismatch_not_502` — exact F10
   reproduction (single-patch0 mesh + lid/fixedWalls 0/p,U). POST
   /api/import/{id}/solve via TestClient must return HTTP 409 with
   `failing_check: mesh_bc_mismatch` and a remediation hint
   referencing /setup-bc. The persona must NOT see HTTP 502
   solver_diverged with a cryptic patch0 IO error.

2. `test_solve_returns_409_bc_not_setup_after_mesh_invalidation` —
   after `_invalidate_stale_bc_after_mesh_regen()` runs, 0/ is gone.
   /solve must NOT return mesh_bc_mismatch (no inconsistency to
   detect; nothing in 0/ to validate against). The route may
   surface 503/409/502 depending on docker availability, but the
   key contract is "no Cannot find patchField entry" string in
   the response.

3. `test_setup_bc_then_solve_state_is_internally_consistent` —
   post-condition: a clean post-setup-bc state with matching mesh
   patches and 0/<field>/boundaryField keys must pass
   `_check_mesh_bc_consistency()` (returns None). Locks in the
   contract that any future change to setup-bc that authors a
   state the pre-flight rejects will fail this test.

## Why this is the right E2E layer

A full Steps 1-5 integration test requires Docker + cfd-openfoam
container + ~60s solver wall-time per case × 3 cases ≈ 3-5min,
which would slow CI dramatically and add fragility to test runs.

The contract tests above cover the **load-bearing** invariant: when
the workbench is in an inconsistent mesh-vs-BC state, the persona
sees a clear actionable 409 instead of a cryptic 502. That's the
F10 fix promise. The full happy-path /solve → SolveSummary →
verdict flow is covered by `scripts/dogfood/live_partial_run.py`
(R7 in DEC-V61-184).
