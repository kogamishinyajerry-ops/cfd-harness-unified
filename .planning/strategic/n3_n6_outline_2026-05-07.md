## 1. N3 · Physics / Materials Layer

**Goal**: Engineer can declare fluid + thermal + turbulence regime with a single-screen contract; CaseProfile tolerance maps to regime; solver choice is a derived consequence (not a separate manual choice).

**Why now (post-N2)**: N2 establishes mesh as engineer-driven; without physics, the mesh has no purpose. N3 unlocks the path to N4 (which will use the regime to default solver dict).

**Sub-DEC decomposition (planned)**:

| Sub-DEC | Capability | Risk | Codex pre-merge? |
|---|---|---|---|
| N3.0 (charter) | N3 phase plan + sub-DEC sequencing | low | no (charter-only) |
| N3.1 | `MaterialContract` schema (fluid: name + ρ + ν + Pr; thermal: cp + k; with literature citation field) | medium | per Opus confidence |
| N3.2 | `RegimeContract` schema (laminar / RANS-RAS / RANS-kOmegaSST / LES-stub; with applicability bounds Re/Ma/y+) | medium | per Opus confidence |
| N3.3 | Step "Physics" panel UI (Beginner: presets / Power: full editor) — slots into Step 3 left rail OR new "Physics" tab in Step 3 viewport | medium | per confidence |
| N3.4 | Solver derivation: regime → solver name (icoFoam / simpleFoam / pimpleFoam / buoyantSimpleFoam) — read-only mapping table; engineer can override in N4 | low | no |
| N3.5 | CaseProfile tolerance binding: regime → default tolerance template (uses existing CaseProfile machinery) | low | no |

**Four-question gate per sub-DEC** (Blueprint v3 §5):

| Sub-DEC | Q1 LLM offline? | Q2 artifacts? | Q3 audit explainable? | Q4 AI advisory only? |
|---|---|---|---|---|
| N3.1 | ✅ user types ρ/ν | ✅ written into case `constant/transportProperties` | ✅ CaseProfile shows binding | ✅ no AI surface yet |
| N3.2 | ✅ user picks regime | ✅ written into case `constant/turbulenceProperties` | ✅ regime applicability shown | ✅ no AI surface yet |
| N3.3 | ✅ UI is form, not AI chat | ✅ same as N3.1+N3.2 | ✅ Completeness card updates | ✅ |
| N3.4 | ✅ derivation table is constant code | ✅ shows derived solver | ✅ trail records derivation | ✅ |
| N3.5 | ✅ tolerance binding is code map | ✅ tolerance written | ✅ tolerance source shown | ✅ |

**Out of scope for N3**: compressibility transitions (Mach > 0.3 deferred), multi-phase, combustion, radiation, magnetohydrodynamics. (M3+ in roadmap_v2 splits these as sub-milestones.)

**Risk register**:
- regime applicability bounds are research-derived → cite source in metadata, never auto-warn (engineer reads citation, decides)
- solver derivation table grows N×M; keep ≤8 regimes initially
- material library bootstrap: ship water/air/oil at v0; engineer-defined materials defer to N3-extend

**Estimate**: ~600 LOC backend + ~500 LOC frontend + ~250 tests across 6 sub-DECs.

## 2. N4 · BC + Solver Unification

**Goal**: Step 3 (BC face annotation) + Step 4 (solver dict editor) merge into one **"Physics setup workbench"** view that holds: face annotations · BC type per patch · solver dict (fvSchemes / fvSolution) · URF · controlDict params. Engineer sees the whole physics-setup state in one screen, not split across steps.

**Why now (post-N3)**: N3 produces the regime. N4 lets engineer translate regime + geometry into a runnable case.

**Sub-DEC decomposition (planned)**:

| Sub-DEC | Capability | Risk | Codex pre-merge? |
|---|---|---|---|

## 4. N6 · AI Advisor Stack (RAG-backed)

**Goal**: Operationalize the V130 "AI 仅两个入口 — 审查 / 诊断" promise. Build the read-only AI advisor surfaces with RAG-backed knowledge: (a) **case review** advisor — given a case state, lists potential issues and citations; (b) **diagnose** advisor — given a failure log + checkMesh output + residual trace, hypothesizes failure mode + cites relevant docs.

**Why parallel-eligible after N3**: N6 reads case state but does NOT mutate it (V132 contract). It depends on case-state shape (stable post-N3) but NOT on solver/post-process. N6 sub-DECs may interleave with N4 / N5 if engineer bandwidth permits, AS LONG AS the four-question gate (especially Q4) holds.

**Sub-DEC decomposition (planned)**:

| Sub-DEC | Capability | Risk | Codex pre-merge? |
|---|---|---|---|
| N6.0 (charter) | N6 phase plan + RAG architecture choice + advisor surface contract | medium | yes (charter sets advisor contract) |
| N6.1 | RAG corpus build: OpenFOAM user guide + tutorial dicts + selected papers (with citation metadata) → vector index | medium | per confidence |
| N6.2 | "AI 审查" route (`GET /api/cases/{id}/ai-review`): reads case state, returns list of `ReviewFinding{severity, area, message, citation, recommended_change(metadata-only)}` | high | yes (V132 contract — must register in MUTATING_ROUTES as **non-mutating**, Layer-A test) |
| N6.3 | "AI 诊断" route (`GET /api/cases/{id}/ai-diagnose?problem={key}`): reads logs/checkMesh/residuals, returns `DiagnosisHypothesis{failure_mode, likelihood, evidence, citation, suggested_fix(metadata)}` | high | yes (same as N6.2) |
| N6.4 | UI integration in Engineer Control Rail bottom: AI Coach panel renders findings/diagnoses as text + copy buttons (NEVER apply buttons) | medium | per confidence |
| N6.5 | LLM-offline degradation: when `LLM_PROVIDER=disabled`, advisor surfaces return rule-based advice (subset of N6.2 templates from N2.4 + similar) — workbench remains 100% functional | medium | per confidence |

**Four-question gate per sub-DEC** — N6 makes Q1 and Q4 the critical filter:

| Sub-DEC | Q1 LLM offline | Q2 artifacts | Q3 audit | Q4 advisory only |
|---|---|---|---|---|
| N6.1 | ✅ corpus is local (no LLM call to query index) | ✅ vector index file | ✅ corpus version + SHA | ✅ |
| N6.2 | ✅ N6.5 fallback to rule-based | ✅ structured JSON response logged | ✅ each finding has citation | ✅ Layer-A registered as non-mutating |
| N6.3 | ✅ N6.5 fallback | ✅ structured response | ✅ evidence chain logged | ✅ same |
| N6.4 | ✅ when offline, panel shows rule-based output with "LLM unavailable, showing rule-based" banner | ✅ panel state captured in trail | ✅ user-visible advisory disclaimer | ✅ no apply button |
| N6.5 | ✅ THIS IS the gate | n/a | ✅ degradation mode logged | ✅ |

**Out of scope for N6**: multi-turn AI dialog state (deferred), AI-authored DEC writeups (NEVER), AI-driven case parameter sweep (NEVER).

**Risk register**:
- RAG ingestion of OpenFOAM docs is large (~500MB index); vector store choice matters (chromadb/qdrant local vs cloud — local mandatory per Q1)
- "AI cannot mutate" contract is contract-test-enforced (V132 Layer-A); any new dispatch path requires registry update — N6.2/N6.3 must be added to MUTATING_ROUTES with explicit `is_mutating: False` per V132 conventions
- LLM provider abstraction must support hot-swap (OpenAI / Anthropic / Ollama local) — interface contract, not a per-provider hard coupling
- Citation hallucination risk (LLM cites non-existent docs); mitigation: each citation must reference a corpus file SHA the system actually ingested; verify before display

**Estimate**: ~800 LOC backend + ~600 LOC frontend + ~400 tests across 6 sub-DECs.
