## Codex summary (verbatim)

> The new transonic extractor/gate has a few logic issues that can misjudge
> otherwise valid cases. In particular, it mixes data from different
> simulation times and computes x/c in an origin-dependent way, both of which
> can produce incorrect verdicts once the scaffold is exercised on real runs.

## Findings (verbatim)

- [P1] Align forceCoeffs with the same snapshot as Cp/probe data —
  src/transonic_airfoil_extractor.py:418-425
  When `coefficient.dat` contains time steps newer than the latest
  `freestreamProbe`/`airfoilSurface` write—which is the normal case if
  `forceCoeffs` writes every step but the probe/surface FOs write only at
  `writeTime`—`cl_fc`/`cd_fc` come from a later state than the Cp field and
  measured freestream. That means C6 and the shock sanity gates can compare
  different flow states, so a still-relaxing run may flip between SANITY-PASS
  and SANITY-FAIL for reasons unrelated to the actual physics.

- [P2] Normalize shock x/c against the leading edge, not global x —
  src/transonic_airfoil_extractor.py:453-455
  These `x/c` values are computed as `x / chord`, so any valid case whose
  geometry is translated in x (for example, quarter-chord at `x=0` or an
  imported mesh that is not LE-based) will report a shifted Cp profile and
  `shock_xc`. The same physical solution can then fail the `(0.2, 0.9)` shock
  band or miss future profile anchors solely because of coordinate origin,
  even though `split_surfaces` has already identified the leading edge via
  `min x`.

- [P2] Check declared Mach/alpha directly against the gold target —
  src/transonic_airfoil_gate.py:326-333
  C0a/C0b only require the measured probe to be close to both the declared
  BCs and the gold target. If the measured value sits between them, both
  checks can pass even though the declared operating point itself is outside
  tolerance (nearly 2x the configured band in the worst case). That weakens
  the documented `measured ≈ declared ≈ gold` contract and lets a slightly
  mis-specified `0/` setup be reported as SANITY-PASS.

## Adoption

| Finding | Fix |
|---|---|
| P1 snapshot mixing | Surface write defines `t_snap`; probe row + forceCoeffs row both selected AT `t_snap` (atol `max(1e-9, 1e-6·max(1,t))`), no row at t_snap → fail-closed raise. Default test fixture now carries a later junk row that selection must ignore. |
| P2 origin dependence | `x/c = (x − x_LE)/chord` with x_LE from the surface's own min-x; plus a 2% chord-vs-x-extent consistency check (scaled/partial surface rejected). Translation-invariance + scale-rejection regressions added. |
| P2 missing third leg | C0a/C0b now require all THREE pairwise legs (measured-declared, measured-gold, declared-gold); two measured-in-between regression tests added. |
