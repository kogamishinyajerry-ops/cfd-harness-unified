## Codex summary (verbatim)

> The patch fixes the originally reported issues, but it also introduces a
> stale-row selection bug for restarted runs and an over-strict chord-span
> check that can reject legitimate surface outputs. Either case can make the
> transonic gate misjudge or unnecessarily block valid replay cases.

## Findings (verbatim)

- [P1] Prefer the last row when snapshot times are duplicated —
  src/transonic_airfoil_extractor.py:210-212
  On restarted OpenFOAM runs that append duplicate `Time == t_snap` rows to
  `surfaceFieldValue.dat` or `coefficient.dat`, this selection keeps the
  first exact match because ties never replace `best` (and
  `_select_at_time()` below has the same first-match behavior). The latest
  `airfoilSurface/<t_snap>/p_aerofoil.raw` file is fresh, so the extractor
  can still mix that surface with stale pre-restart probe/force rows and
  report the wrong C0/C6 verdict. The row-at-time logic needs to prefer the
  last matching row, not the first one encountered.

- [P2] Don't reject valid meshes based on face-centre x-span —
  src/transonic_airfoil_extractor.py:519-523
  This compares the declared chord against the x-range of `p_aerofoil.raw`,
  but that file contains one sample per patch face center, not the actual
  LE/TE vertices. On a valid but moderately coarse airfoil mesh, the first
  and last face centres can easily sit more than 2% inside the true ends, so
  otherwise correct replay bundles will now raise `geometry/chord mismatch`
  purely because of surface discretization. That makes the new fail-closed
  check reject legitimate cases.

## Adoption

| Finding | Fix |
|---|---|
| P1 duplicate-time ties | Both probe row selection and `_select_at_time` now keep the LAST row among ties (`<=` comparison) — the post-restart row wins. Two restart-duplicate regression tests added. |
| P2 face-centre span | Asymmetric band: span may fall SHORT of chord by ≤10% (face-centre discretization can only shrink), may EXCEED by ≤2% (never legitimate). Partial (0.85×) and scaled (1.05×/1.5×) surfaces still rejected; 0.95× face-centre-like shrink accepted (regression tests for all four). |
