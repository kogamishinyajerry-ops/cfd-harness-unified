## Codex summary (verbatim)

> The new observatory surface is not fully reliable yet: it mis-parses
> existing Codex report references and can fabricate replay steps for
> unresolved arcs. Because this page's value depends on faithfully
> reflecting real governance artifacts, those issues make the patch
> incorrect.

## Findings (verbatim)

- [P1] Strip annotations from `codex_tool_report_path` before lookup —
  ui/backend/services/agent_crew.py:245-257
  This parser only understands brace expansion and comma-separated bare
  paths, but several DECs that already qualify for `/agent-crew` use
  annotated values such as `path1; path2` or `path.md (filled by main
  session ...)` in `codex_tool_report_path` (for example DEC-V61-209 and
  DEC-V61-217). Treating the whole field as a literal filename makes
  `/api/agent-crew` mark those reviews as `MISSING` and drop their real
  Codex history, which breaks the page's core accuracy guarantee.

- [P2] Only add a repair step when another Codex round follows —
  ui/frontend/src/pages/agent_crew/components/ArcReplay.tsx:47-54
  The replay is supposed to derive steps from recorded artifacts, but this
  branch appends `总师修复` after every non-approval verdict, including the
  final `CHANGES_REQUIRED`/`UNPARSED`/`MISSING` round. For any arc whose
  latest review is unresolved (the current dataset already has `MISSING`
  examples), the UI shows a fix step that never actually happened, so the
  observatory tells a false collaboration story.
